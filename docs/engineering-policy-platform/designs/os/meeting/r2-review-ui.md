## 1. 引用抽查（4 处 + 1 处顺带命中）

### 1.1 `app.js:170-200` 本地算判定 —— **成立，且我补一处他们没写到的**

【实测/读码】`validate()` 全在浏览器内：`:174` 判 checker 未实现、`:177` 判无验证器供证、`:181` 判规则体缺字段、`:185` 判未知字段、`:191` 判 codes 大小写、`:197-198` **把 `severity` 直接映射成 `block` / `allow_with_warnings`**。X6 的结论锚点 `:198` 逐字对得上。
**补一处**：`:361-366` 是**第二个独立本地判定点**——候选行的"预演"按钮只按 `spec.validators.length` 就写 `'预演通过'` 并 `:367` 禁用按钮。C1 的验证条目"扫描决策字面量"扫不到它（它不含 `block`/`allow_with_warnings` 字面量），但它是同一类缺陷。
**收敛要求**：C1 的扫描清单要加两类模式——① `severity` 作输入、决策值作输出；② **`预演通过` / `加载成功` 这类"结论性中文文案"**（对比 A1 的补法②）。

### 1.2 `build_site.py` 的静默硬编码回退 —— **成立，且我能给出更锋利的对照**

【读码】`:212-216` 的 `try: from policy.checkers import SUPPORTED_CHECKERS` 失败时，`:216` 直接给 6 个字面量，**不记录任何错误**。X8 的范围 `:213-219` 成立（精确赋值在 `:216`）。
**比他们写的更强的证据**：同一个函数内，验证器注册表读取失败**会**记录（`:209-210` 写 `data["meta"]["registry_error"]`），规则集读取失败**也会**记录（`:173-174` 写 `rules_error`）。所以这不是"风格差异"，是**同一个函数里三条数据源两种纪律**——回退那条是唯一的例外。A14 的"偏离惯例，不是风格问题"这句话，我可以从 `:173-174` `:` `:209-210` `:` `:215-216` 三处并列给出证据。
**判定：同意，无需收敛。**

**收敛要求**：终稿必须新增一条与 C 系列同级的条目（我给编号 **C16**）：「没有对应路由的操作**不得渲染按钮元素**；确需保留认知锚点时渲染 `aria-disabled="true"` 的可聚焦按钮，其说明必须含三段：缺口编号 + 替代命令 + 为什么不能在前端补」（见 §5 第 7 条）。

## 4. 与 `r1-layouts.md` 的冲突（6 条，逐条给收敛方案）

**冲突 1：板块命名 —— S1–S9 与 F2 六层是两套坐标系。**
`r1-modules` V1 明确否决"按六层拆板块"，而我 R1 §1 把六层名直接用作导航一级。
**判定：两者都对，问的不是同一个问题。** S1–S9 回答"**谁能产生结论**"（权力/调用边界）；六层回答"**职责属于哪一类**"（架构分层）。V1 的否决理由（"按层拆会把'唯一入口'写成'每层一个入口'"）对**模块拆分**成立，对**导航分组**不成立——导航分组不创造入口，只要每个页面的动作都落到同一条路由/CLI。
**收敛方案**：终稿导航一级保留六层名（满足口径 §1 的三处同改与 Lead 的"板块名对得上 F2"要求），**每个页面头部固定一行 `S 板块：S5`**，页面内标签页按 S 切（检索=S5 / 受控执行=S3 / 验证器=S4）。我承认原方案丢了 `r1-modules` §1 最有价值的那一列（"该板块不行使的权力"）——终稿每个页面必须带这一列。

**冲突 2：B1 未修前，P8「治理写入」页该不该存在。**
我 R1 把 P8 留作【提案】页（整页灰色）；`r1-modules` 把它排在第 4 步；`r1-constraints` O10 说"先修 B1 再谈 P2 是必要条件"。
**判定：红队对我，我需要退一步。** 我原以为"灰色 + 悬停说明"是无害的锚点。抽查 §1.1/§1.2 之后这条站不住：`app.js:384` 展示的工具是 `orc.policy.edit`（`approval: required`），而**运行期实际会选 `orc.fs.write`**（R1 复核成立）。也就是说，**只要 B1 未修，任何展示"提交会走审批"的界面都在给一个假的审批承诺**——灰色也救不了它，因为它展示的是**内容**而不是按钮状态。
**收敛方案（可直接落笔）**：P8 保留骨架但**在 B1 修复前只显示一段文字**：「本页在 B1 修复前不提供写入视图：运行期对 `policies/**` 的新建文件会选择 `approval: none` 的工具（`src/orchestration/nodes.py:93-97`、`registry/tool-registry.yaml:293-315`），任何审批展示都与实际执行不一致。今天改规则的路径是 `<命令>`。」并**删掉 `action_hash` / `post_checks` / 审批人 三个展示块**。

**冲突 3：失败语义表 vs C5/C6 —— 我漏了一条分支，C6 比我严一格。**
C5 我基本覆盖（504/503/429/未知码 → 中性灰"没有结论"），但**漏了 401/403 的归类说明**（我把它混进"凭据或边界不被接受"一行，没写它同样不是"判定结论"）。
C6 的要害在 `include_evidence` 缺省：响应**没有** `skipped_rules` 键（`runtime.py:572-573`），界面只拿到 `allow` + `summary.skipped>0`。我 R1 §7 只在格子内写了一句"须显示'未请求明细'"、U5 写了"不补默认值"，**都没有把它升级成请求级硬规则**。
**收敛方案**：① 终稿加一条与 U 系列并列的规则：「**界面所有 `evaluate` 请求必须显式带 `include_evidence=true`**；未带时不得渲染任何"通过"文案」；② 我坚持比 C6 更严的半句——绿色门槛是 **`every(skipped_rules[].reasons)` 非空**，不是"存在 reasons"。

**冲突 4：角色可见性 vs N5 —— 我写"ops 额外看到 metrics 入口"，这句话今天无法实现。**
我 R1 §2.1 自己写了"当前身份/角色：**不可用**（无路由）"，却在 §3 各页写"ops 可打开指标"。N5（无多用户会话、无前端身份）说明界面**不知道**当前角色；用客户端声明当权限正好撞上 A8/C 系列。
**收敛方案**：终稿把"角色可见性"改名为「**角色可服务性**」，并规定三条：① 页面**不隐藏**任何入口（隐藏即客户端做了授权判断 → 第二份逻辑）；② 未授权时渲染**服务端返回的 401/403 原文**；③ ops-only 入口（metrics）默认**折叠不隐藏**，展开即发请求、由服务端 403 说话。

**冲突 5：把 S3/S4/S5 压进一个「能力层」页面，是否丢掉了板块独立性。**
我 R1 P3 一页三标签；`r1-modules` 把它们列为三个独立板块，各有"不行使的权力"。
**判定：页面归属可以合并，权力边界不能合并。** 收敛：P3 保留三标签，但**每个标签头部必须并列该 S 板块的"唯一入口"与"不行使的权力"**（照抄 `r1-modules` §1 表对应行），否则合并就是把三条不同的红线折成一条。

**冲突 6：数字口径 —— 我的 V20 与双方的数字写法正面冲突。**
R2/R3/R4/R10 证明：规则集、语料、索引在会议期间都在变，而 `r1-modules:168/:232` 与 V21 都写成了**裸数字 / 裸结论**。
**收敛方案**：终稿凡出现计数或哈希，一律写成「值（取数时刻，取数命令）」。V21 的措辞改成：「六条门禁在某次取数时全部退出 0；**这不表示规则集或索引与上次相同**（R10 反例）」。

## 6. 被推翻的地方（我 R1 文档里站不住的部分）
