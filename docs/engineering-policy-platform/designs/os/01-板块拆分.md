# 01 · 板块拆分（平台操作系统）

> 本文是 [平台操作系统总体设计](README.md) 的第 1 部分，结论由 [04-会议纪要与裁决](04-会议纪要与裁决.md) 的 D1–D15 背书。
> 逐条证据见 [meeting/r1-modules.md](meeting/r1-modules.md) 与 [meeting/r2-review-kernel.md](meeting/r2-review-kernel.md)。
> 标记：【实测】当场跑过并留退出码；【读码】`file:line`；【提案】今天不存在。

## 0. 一页结论

1. 这个仓库**已经是一个操作系统**——缺的不是内核，是第 9 块（操作台）。所谓「为本仓库做一个操作系统」，正确读法是：
   **把已有 8 块板子的边界写清楚，再补一块只读的操作台**，而不是新写一个系统。
2. 切分线只有一条：**谁能产生结论**。只有 S1 判定内核产出 `allow` / `allow_with_warnings` / `block`（D1）；
   其余八块分别翻译、执行、产证据、取语料、传协议、排下一步、复跑门禁、显示。
3. 每块板子最有价值的一列不是「它能做什么」，而是「**它不行使什么权力**」。这一列是阻止板块膨胀成第二份判定逻辑的第一道约束。
4. 评审提出的三个阻塞项已在 2026-09-22 修复并由 `meeting/r4-remediation-verification.md` 复核：
   B1（受保护写入统一人工审批）、B2（HTTP 面暴露真实漂移）、B3（幂等超限显式失败）。
5. 「操作系统」这个隐喻**只用来解释，不用来推导**（D12）：凡写进接口、路由、字段、按钮的决定，依据必须回到 `file:line` 或 `AGENTS.md` 约束编号。

## 3. 隐喻不成立的地方（与上表同等重要）

**M1 没有进程隔离。** namespace 只是台账键前缀（`<adapter.namespace>:<event_id>`），平台没有容器、没有 chroot、没有把 Agent 关进独立文件树。
会写出什么错误设计：把 adapter 边界当安全边界，去设计「Agent A 读不到 Agent B 的工作区」。
**正确形态**：隔离只有三条——命名空间化的台账键、声明式能力上限、路径范围校验；文件系统与进程级隔离属于运行时，本平台自述**不在范围内**（约束 17）。

**M2 编排不是调度器。** 它没有配额、没有优先级、没有队列；`limits` 给的是**硬上限**，击穿即 `needs_human`。
会写出什么错误设计：把 checkpoint 当任务队列、把 RunReport 当平台审计源、设计「多租户共享调度」。
**正确形态**：编排只回答「下一步做什么」；要观察进度读它自己的 status，要判定读内核的 Decision。

**M3 `policies/` 不是可自由读写的文件系统。** 规则集是**整批原子加载**，任一文件失败即整批不加载；没有「单条卸载」这种操作语义。
会写出什么错误设计：给界面一个通用 YAML 编辑器或「保存即生效」。
**正确形态**：写入只有两条路——改数据 + 重新审核（哈希绑定），或走 S3 的受控执行链。

**M4 内核不是特权态，界面不是第二个内核。** 判定与执行的分权靠**数据结构**（Decision、证据、授权），不靠硬件特权级。
会写出什么错误设计：「既然有系统面板，面板就该能做系统能做的一切」，包括写入、重载、改配置。
**正确形态**：把 OS 当**仪表盘 + 申请单**（D14）：能看见、能发起、不能自己执行。

**M5 「系统调用」不是稳定 ABI。** 决策协议版本、传输协议版本、编排状态版本**各自演进**（约束 7 / 31 / 36）。
会写出什么错误设计：用一个版本号统辖三层，或把平台 Phase 当协议版本，或让界面自己推算版本。
**正确形态**：每个消费方按自己的版本判定兼容性；看不懂就拒绝。

**M6 设备驱动没有自动发现，也没有热插拔。** 工具表是 YAML 白名单 + 已审核哈希；升级 Agent 必须**先更新工具表并补契约测试**（约束 8）。
会写出什么错误设计：运行期自动发现 Agent / 自动注册工具，或让模型自己声明「我这个动作属于哪一类」（约束 13 明确禁止）。

**M7 「安装」没有依赖求解，也没有签名。** 已审核哈希是**内容哈希清单**，记录的是「谁在何时审了哪份哈希」；它只防「改完忘了重新审核」。
会写出什么错误设计：把已审核哈希当防篡改承诺，用绿勾掩盖这个边界。
**正确形态**：审核是流程，哈希是它的凭证；这条边界必须**显示在界面上**（见 03 §6）。

## 5. 每块的接口面与失败关闭状态（压缩版）

### 5.1 S1 判定内核
输入：规则目录 + **显式**上下文（file / layer / language / module / project / agent / operation / workspace）+ 可选证据。
输出：`Decision` 三值 + `matched_rules` / `skipped_rules`（后者必须带原因）+ `rule_set_hash`。
失败关闭：CLI 退出码 `0` 通过 / `1` 违规或漂移 / `2` 配置或执行错误；未知 checker、未知 scope 维度**加载即报错**；「没有任何验证器为某 checker 供证」→ `critical`（约束 20）。

### 5.2 S2 接入与适配
输入：Agent 线协议事件 + 能力声明（manifest / adapter 配置）。输出：规范事件 + Decision + 面向 Agent 的原因码（受控枚举）。
失败关闭：Hook 只有 `exit 0` 放行 / `exit 2` 阻断（`exit 1` 刻意不用）；能力不足 → `capability_unavailable`（**拒绝**，不是跳过治理）。

### 5.3 S3 受控执行
输入：`ActionRequest`（工具 + 规范化参数 + 主体 + 权限 + 上下文摘要 → `action_hash`）+ 已审核注册表 + 可选人工审批记录。
输出：`PreDecision` + 逐项检查结果。**提交节点的唯一判据**：`approval` 检查项 `status == "passed"`；`skipped` / `failed` / 过期都不等于通过（D8）。
失败关闭：任一检查项 `FAILED` 即 block；审计或台账不可写则受治理动作**不执行**；事后验证三态 `repair_required` / `inconsistent` / `unsupported`。

### 5.4 S4 验证器
输入：目标文件 + workspace + 配置根 + 变更集 + 允许的验证器集合。输出：带验证器 id/版本、规则 id、文件行号、严重级别、退出码与配置哈希的证据。
失败关闭：缺失 / 版本不符 / 超时 / 崩溃 / 配置错误 / 输出非法一律阻断；未知 checker 在**加载阶段**报错。

### 5.5 S5 检索与语料
输入：语料清单 + 查询文本 + 显式 `AccessScope`。输出：三态 `ok` / `empty` / `unavailable` + 带来源路径、URL、许可、文本哈希的命中项。
失败关闭：不可用原因显式枚举（空查询 / 无结果 / 缺索引 / 检索失败 / 无权限）；哈希漂移必须让 `verify` 退出 1；**绝不用模型记忆兜底**。

### 5.6 S6 服务化传输边界（**6 条契约路由 + 1 条运行时 OpenAPI 端点**）
| 方法 | 路径 | 认证 | 说明 |
| --- | --- | --- | --- |
| POST | `/v1/policy/evaluate` | Bearer | 判定（与本地整份相等） |
| POST | `/v1/knowledge/retrieve` | Bearer | 检索 |
| POST | `/v1/validation/evaluate` | Bearer | 验证器证据 |
| GET | `/v1/health/live` | 免令牌 | 存活 |
| GET | `/v1/health/ready` | 免令牌 | 就绪（不通过则拒绝启动） |
| GET | `/v1/ops/metrics` | Bearer + 运维角色 | 指标 |
| GET | `/v1/openapi.json` | **未认证** | 框架自带，**不在契约 paths 内**，必须单独登记 |
失败关闭：错误码 → HTTP 状态由 `errors.STATUS_BY_CODE` **推导**（超时 504；依赖不可用 503；限流 429；幂等键冲突 409；认证 401 / 403 / 404 / 413 / 415）。响应体不能完整写入幂等台账时返回 **503 `idempotency_unavailable`**，不写入残缺条目，也不产生 `Idempotency-Replayed` 空壳。
可达性（D6）：`capability_unavailable` / `evidence_unavailable` / `policy_unavailable` / `query_invalid` / `target_invalid` 在今天**存在但 0 抛出点**，界面不得为它们画分支。

### 5.7 S7 编排（消费者）
输入：任务/需求（只留摘要）+ checkpoint + 平台凭据（`rule_set_hash` / `index_version` / `tool_schema_hash` / 协议世代）。
输出：`RunReport`（含 engine 与失败码）+ 原子替换的 checkpoint。
失败关闭：终态只有 `blocked` / `needs_human` / `failed`，由 `STATUS_BY_CODE` 决定；**未登记的失败码一律按 `failed`**；恢复发现「开工未结算」→ `side_effect_unknown` 交给人。

### 5.8 S8 证据与门禁
输入：工作树改动范围 + CI 事件。输出：步骤级结论 + `.tmp/artifacts/` 下的阶段证据。
失败关闭：`ci_local.py` 只有 `0` / `1`；环境不具备时**按环境跳过**并写 reason（绝不把「跑不了」记成 pass）；**门禁绿只证明检查项通过，不证明规则集/索引未变**（D10）。

### 5.9 S9 操作台【提案】
输入（今天）：由生成器预先生成的静态数据；输出（今天）：静态页，无写路径、无服务端挂载。
失败关闭：`504` / `503` / `429` / `idempotency_unavailable` 一律渲染「没有结论」；`skipped_rules` 与 allow 视觉分开；B2 修复后漂移字段来自服务端真实结果，仍按「未核对 / 一致 / 漂移」三态展示。

## 6. 落地顺序

见 [04-会议纪要与裁决](04-会议纪要与裁决.md) §2 D13（P-1 先修 → P0 只读视图 → P1 流程化 → P2 申请单 → P3 溯源与覆盖）。
一句话理由：**界面是唯一没有自己的结论、却最容易长出结论的一层**；先做界面等于先造第二份判定。

## 7. 不变量（写进代码与页面都要守）

| # | 不变量 | 违反后果 |
| --- | --- | --- |
| I1 | 只有 `policy.engine.evaluate` 产出三值结论 | 审计失去意义 |
| I2 | 未知字段 / 枚举 / 维度 / 版本一律报错 | 静默降级 |
| I3 | 失败关闭：超时、不可达、空壳、缺证据 = 更严 | 把「不知道」当成「允许」 |
| I4 | `skipped` ≠ 通过；退出 0 ≠ allow | 假绿灯 |
| I5 | 数字与哈希必须带取数时刻与取数命令 | 文档和界面当天过期 |
| I6 | 授权绑参数、单次使用；审批不由客户端自算 | 审批装饰化 |
| I7 | 审计不可写则受治理动作不执行 | 无证据的副作用 |
| I8 | 数据契约改动 = 重新审核 + 补测试 | 哈希保护失效 |
