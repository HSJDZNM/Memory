## 0. 前置条件与安装（Phase 0 起）

| 项 | 要求 |
| --- | --- |
| Python | ≥ 3.11（本机验证 3.13.11） |
| 依赖 | 从 `requirements.lock` 安装（固定直接依赖版本；仓库不提交 `uv.lock`） |
| 可选工具 | Ruff `>=0.6,<1`（本机实测 0.14.13；`STYLE-*` 规则的证据来源，缺它时相关规则**失败关闭**） |
| 可选 | dsh（Phase 2 真实链路）、mypy（端口就位但未启用规则）、git（`--changed-from-git`）；本机实测缺 dsh 与 mypy，`python -m validators.cli probe` 会报 1 个关键工具不可用 |

```powershell
# 方式一：uv（推荐）
uv venv
uv pip install -r requirements.lock

# 方式二：现有解释器
python -m pip install -r requirements.lock
```

本项目**不把 `src/` 装进 site-packages**。模块要靠 `PYTHONPATH=src` 找到：

```powershell
# 每次新开终端都要设一次（或用 uv run，它把项目环境接上）
$env:PYTHONPATH = "src"
python -m policy.check --check-rules
```

学习手册不受这条限制：各阶段 notebook 与 `walkthrough.py` 会自己把 `src/` 与 `tools/` 加进搜索路径。

## 1. 五分钟上手（Phase 0 / 1）

```powershell
$env:PYTHONPATH = "src"

# ① 规则集自身是否可加载（配置损坏 → 退出码 2）
python -m policy.check --check-rules

# ② 反例：Controller 直接依赖 Repository（Phase 5 起依赖由 AST / 依赖图给出）→ 退出码 1
python -m policy.check examples/bad_controller.py --layer controller

# ③ 正例 → 退出码 0
python -m policy.check examples/good_controller.py --layer controller

# ④ 范围不匹配：layer=service 时 ARCH-001 不参与判断，输出会写明跳过原因 → 退出码 0
python -m policy.check examples/good_controller.py --layer service

# ⑤ 机器可读输出：顶层是 CLI 包装，result 就是带 schema_version 的决策载荷 → 退出码 1
python -m policy.check examples/bad_controller.py --layer controller --json
```

**退出码是唯一的结论口径**。

| 退出码 | 含义 |
| --- | --- |
| `0` | 通过（`allow`）；或命令成功 |
| `1` | 发现违规（`block` / `allow_with_warnings`，含需要人工审批的 block）；或发现漂移 / 无结果 |
| `2` | 配置或执行错误（规则不可读 / 规则损坏 / 上下文不完整 / 未知 checker / 请求不合法 / 审计链损坏） |

## 2. 规则判定（Phase 1 · `python -m policy.check`）

| 参数 | 说明 |
| --- | --- |
| `file` | 待检查文件（仓库相对路径或绝对路径） |
| `--rules DIR` | 规则目录，可重复；默认 `policies/` |
| `--layer LAYER` | 架构层（安全关键维度）；不传时按文件名推断并在输出中标明 |
| `--language` | 上下文语言；**传空字符串表示语言未知**，语言相关规则会被跳过 |
| `--module` | 模块名。刻意不从路径推断：猜错会让规则在错误范围生效 |
| `--operation` | 受控枚举 `read / create / edit / delete / execute` |
| `--dependencies A,B` | 显式声明依赖，**覆盖** AST / 依赖图证据（重放历史场景用） |
| `--changed FILE` | 本次变更集（可重复）；测试类规则需要它，缺失属于证据不足 |
| `--workspace` / `--config-root` | 被验证项目根 / `validation/` 所在目录 |
| `--validators A,B` | 只运行这些验证器（allowlist）；**没跑的 checker 会失败关闭** |
| `--trace-id` / `--task` | 只记录与传递，**不参与范围匹配**（`task` 是给人看的描述） |
| `--agent` / `--project` | **参与范围匹配**：它们与 `--layer` / `--language` / `--module` / `--operation` 同级，是 scope 的 6 个已知维度；配了 `scope.agent` / `scope.project` 的规则会命中，否则会写进 `skipped_rules` |
| `--json` / `--check-rules` / `--keep-temp` | 机器可读 / 只校验规则集 / 保留验证器临时目录 |

排查"规则为什么不生效"，先看输出里的 `skipped_rules`。它按维度写明原因（例如 `layer service != controller`）。

## 3. 接入 dsh（Phase 2 + Phase 4）

接线分两层，**缺一层都不生效**。

```text
第一层：把进程内转发插件挂到 profile 上     examples/dsh/profile-patch.yml
第二层：patch 指向的 hooks.json 里声明 Hook 命令   examples/dsh/hooks.json
```

```powershell
# 1) 受治理项目 .policy/ 下放两份配置（从 examples/dsh/ 复制）
#    dsh-adapter.yaml：显式声明 project_root / rules / layers / languages / 内部预算 / principal / registry
#    hooks.json      ：声明 Hook 命令（matcher 留空 = 匹配全部工具）

# 2) 只做接线自检：hooks.json 是否存在、命令是否指向本适配器、内部预算是否小于 dsh 超时
python -m adapters.dsh.hooks --config examples/dsh/dsh-adapter.yaml `
    --hooks-config examples/dsh/hooks.json --self-check     # 实测退出码 0（[policy] self-check ok）

# 3) 真实沙箱闭环（受控临时项目，不指向真实仓库与真实凭据）
python tools/dsh_sandbox_loop.py            # 需要 dsh；没有则按环境跳过（退出码 0 + reason）
```

**Hook 的语义**：读 stdin JSON，`exit 0` = 放行、`exit 2` = 阻断。阻断时 stderr 就是理由。
dsh 对"超时 / 崩溃 / 配置读不到"一律按**放行**处理，所以失败关闭由 Hook 自己保证。
三件事：内部预算（`timeout_ms: 5000`）严格小于 `hooks.json` 的 `timeout: 30`；任何异常转 exit 2；运行期接线自检。

**两条使用注意**如下。

1. `matcher` 必须留空。窄 matcher 会让 dsh 新版本新增的工具或 MCP 工具**绕过**门禁；过滤逻辑放在 Adapter 的工具表里。
2. 受限沙箱里 Hook 起不来（spawn EPERM）时，`dsh_sandbox_loop.py` 判成 `skipped`。
   机制见 [dsh README](../../../src/adapters/dsh/README.md) 第 7.1 节；它写出 `reason` / `reproduce`，不把"跑不了"记成 pass。

## 4. 离线规范检索（Phase 3）

```powershell
# 1) 校验摄取清单：数据集、许可、镜像 manifest 与本地文件哈希（漂移 → 退出 1）
python -m retrieval.cli verify                    # 实测退出码 0（datasets=6 entries=42 | OK）

# 2) 幂等重建索引（SQLite FTS5，产物在 .tmp/retrieval/ 下，可随时删掉重建）
python -m retrieval.cli index
python -m retrieval.cli index --check      # 只问"要不要重建"

# 3) 检索片段 / 组装上下文（--json 得到机器可读载荷）
python -m retrieval.cli query "代码评审需要检查哪些方面" --limit 5
python -m retrieval.cli context "代码评审需要检查哪些方面" --decision tests/fixtures/decisions/block.json

# 4) 查规则溯源：某个规则由哪段文档提炼而来（反向：某个 chunk 被哪些规则引用）
python -m retrieval.cli rules --rule SEC-008      # 实测退出码 0：SQL_Injection_Prevention_Cheat_Sheet.md 的对应小节
python -m retrieval.cli rules --rule ARCH-001     # 实测退出码 1：项目自订规则没有镜像来源
python -m retrieval.cli rules --chunk <chunk_id>

# 5) 索引库统计 / 隔离已知恶意 chunk / 向量检索对照
python -m retrieval.cli stats                     # 实测退出码 0（documents=42 chunks=1013 rule_sources=141）
python -m retrieval.cli quarantine --chunk <chunk_id> --reason "prompt injection"
python -m retrieval.cli vector "代码评审需要检查哪些方面"   # 实测退出码 1：status: unavailable (index_missing)

# 6) 固定评测集基线（FTS5 门槛决定退出码，向量检索只作对照记录）
python tools/retrieval_eval.py --method both
```

**要点**如下。

- 语料、许可、预算、隔离、术语都是数据：改 `knowledge/corpus.yaml` 与 `knowledge/query_expansion.yaml`；
- 检索**无结果**时 `query` 退出码是 `1`；检索**不可用**时 Context 只输出 `knowledge_unavailable`，
  **绝不回退到"模型记忆里的规范"**；
- 权限只来自显式 `AccessScope`：受限数据集要 `--allow-restricted` 才可检索，查询文本不能扩权；
- 结果改变（换 embedding / 改术语表 / 改语料）必须用 `--record` 显式重记基线并递增评测集版本。
- 本节对应口径表的**台阶 2（语料登记）与台阶 3（分块与索引）**，实施批次是 Phase 3；`retrieval.cli rules` 的"无溯源"退出 1 正是**台阶 7 的可选登记**当前为空（见口径表 §2）。

## 5. 受控执行（Phase 4）

```powershell
# 1) Tool Registry 是数据；运行时描述与已审核哈希不一致的工具不可使用
python -m enforcement.cli registry --verify     # 实测退出码 0（tools=9 approved=9）
python -m enforcement.cli registry --show fs.edit

# 2) 只做执行前决策（dry-run：不执行、不占 action_id）
python -m enforcement.cli precheck --request examples/enforcement/edit-allow-request.json

# 3) 受控执行：pre-check → 短时效 grant → 执行一次 → 事后验证（哈希 / diff / 语法）
python -m enforcement.cli execute --request examples/enforcement/edit-allow-request.json

# 4) 高风险动作（pwsh / bash / run_code）默认阻断：先由人工门禁签发与 action_hash 绑定的审批
python -m enforcement.cli approve --request examples/enforcement/shell-approval-request.json `
    --out .tmp/artifacts/approval.json --granted-by alice --roles reviewer --ttl 300
python -m enforcement.cli execute --request examples/enforcement/shell-approval-request.json `
    --approval .tmp/artifacts/approval.json

# 5) 按 trace / action / request 重放审计链；校验审计链完整性与注册表审核状态
python -m enforcement.cli trace --audit .tmp/artifacts/enforcement-audit.jsonl --action-id <id>
python -m enforcement.cli verify --audit .tmp/artifacts/enforcement-audit.jsonl

# 6) 上线自检 / 受控执行闭环
python -m enforcement.cli self-check            # 实测退出码 0（带 exec.pwsh 找不到的 warning）
python tools/enforcement_loop.py
```

**两条使用提示**（来自 README，已实测）：

1. 示例请求里的 `action_id` 是固定的。第二次执行会被**正确地**判成重放（`action_replay`，退出码 1）。
   要重复演示就换一个 `action_id`，或先 `python tools/cleanup.py` 清掉 `.tmp/` 下的台账与审计。
2. 命令类示例（`exec.pwsh` / `exec.bash`）需要本机真的装了对应 shell。
   没有装时结果是 `failed(process_error)` / `repair_required`（退出码 1）；它**不会静默通过**，`self-check` 也会报 warning。
   本机实测正是这个状态：`python -m enforcement.cli self-check` 退出 0 但写出 `exec.pwsh: 本机找不到 'pwsh'`。

改注册表之后必须重新审核，否则该工具**不可使用**。

```powershell
python -m enforcement.cli registry --approve --reviewer <name>
```

## 6. 代码验证器（Phase 5）

```powershell
# 1) 注册表事实 / 外部工具探针（可用性、版本区间、配置文件；缺失即 unavailable，不降级）
python -m validators.cli registry                # 实测退出码 0：7 个验证器
python -m validators.cli registry --show tool.ruff
python -m validators.cli probe                   # 实测退出码 0；本机缺 mypy（缺失或不匹配的关键工具：1）

# 2) 只产出证据（不做 allow / block）
python -m validators.cli check examples/bad_controller.py --layer controller      # 实测退出码 0：只产证据，不判定

# 3) 证据 + 判定（与 policy.check 同一条链路）
python -m validators.cli pipeline examples/bad_controller.py --layer controller   # 实测退出码 1：block

# 4) 测试类规则：按变更集选择最小相关测试（只有 operation=create/edit 才触发）
python -m policy.check tests/fixtures/validators/project/src/shop/order_service.py `
    --layer service --workspace tests/fixtures/validators/project `
    --operation edit --changed src/shop/order_service.py     # 实测退出码 0（allow；ARCH-001 因 layer 不匹配进 skipped_rules）

# 5) 闭环：AST 证据 / 失败关闭 / 测试选择 / 可重放 / 工具可追溯
python tools/validator_loop.py
```

**失败关闭**：不是提示，是阻断。
关键验证器一旦不可用，需要它的规则就以 `critical` 违规阻断。
缺失 / 版本不符 / 超时 / 崩溃 / 配置错误 / 输出非法都算不可用；"没有任何验证器为某个 checker 提供证据"同样阻断。
**同一批里的其他 PASS 抵消不了它**。
语法错误、动态 import 目标不是常量、项目内模块解析失败同样阻断：解析不了的文件不能被判定为"没有依赖问题"。

本节对应口径表的**台阶 6（验证器覆盖）**，实施批次是 Phase 5。

**前提**：`policies/coding/STYLE-*.yaml` 需要 PATH（或当前解释器同目录）上有 Ruff；没有它连正例都会以
`tool.ruff@1.0 unavailable` 失败关闭。先用 `python -m validators.cli probe` 自查。

## 7. 多 Agent 适配（Phase 6）

```powershell
python -m adapters.cli matrix                              # 支持矩阵（full / read_only / unsupported）；实测退出码 0
python -m adapters.cli approve --reviewer <name>           # 审核能力声明（改完 manifest 必须重跑）
python -m adapters.cli check                               # 一致性套件：所有 Adapter 对同一组语义事件给同一套结论；实测 0（87 项检查 pass）
python -m adapters.cli events                              # 每个 Agent 的兼容性 fixture 是否存在
python -m adapters.cli inspect --agent dsh --event tests/fixtures/agent_events/dsh/pre-tool-use-edit-block.json
# 实测退出码 0，但结论写在 JSON 的 outcome_code 里：失败关闭 context_error（fixture 的 cwd 指向合成工作区，路径越界被拒绝，不是 allow）。**退出 0 ≠ allow**
python tools/agent_loop.py                                 # 多 Agent 闭环
```

**新增一个 Agent 的流程**（不需要改核心层）：

1. 在 `adapters/<agent_id>/` 下写三样东西。
   `manifest.yaml` 声明事件名、字段名、工具名、阻断与审批能力；`adapter.yaml` 声明装配；再加最小真实事件 fixture；
2. 实现一个 Adapter（只做协议转换，不猜 layer / language / principal）；
3. `python -m adapters.cli approve --reviewer <name>` 审核；
4. 再依次跑 `adapters.cli events`、`adapters.cli check` 与 `tools/agent_loop.py`；
5. 若能力不足（拦不住写类动作），上限就只能声明成 `read_only`——受治理动作会得到
   `capability_unavailable`，而不是"跳过治理"。

## 8. Policy API（Phase 7）

```powershell
# 1) 装配 / readiness / 传输契约自检（配置、租户、规则集、索引、验证器、观测日志）
python -m policy_api.cli self-check            # 实测退出码 0（2 个租户可服务）

# 2) OpenAPI 契约快照：漂移即退出 1；改契约必须显式评审后 --write
python -m policy_api.cli openapi --check       # 实测退出码 0（与快照一致 api_version=1.0）
python -m policy_api.cli clients            # 客户端清单（--hash 从 stdin 读令牌输出 sha256）；实测退出码 0，3 个客户端

# 3) 进程内最小链路（不开端口）：live → ready → evaluate → retrieve
python -m policy_api.cli smoke --token local-dev-token   # 实测退出码 0；本机 retrieve 段返回 503（该租户索引未建）

# 4) 起服务（默认 http://127.0.0.1:8088；readiness 未过则拒绝启动）
python -m policy_api.cli serve

# 5) 观测日志的对外锚定：封出链末值 / 校验日志是否被删尾或改写
python -m policy_api.cli seal --out .tmp/artifacts/api-anchor.json
python -m policy_api.cli seal --verify .tmp/artifacts/api-anchor.json

# 6) API 闭环（真端口 uvicorn，八类场景）
python tools/api_loop.py
```

**部署数据**见 [`api/policy-api.yaml`](../../../api/policy-api.yaml)。它管租户边界、客户端令牌（**只存 sha256**）、
预算与限额、观测落点；传输契约快照是 [`api/openapi.json`](../../../api/openapi.json)。
仓库里的令牌是演示值（`local-dev-token` / `dsh-agent-token` / `ops-monitor-token`），**不是真实凭据**。

**失败语义**：状态码由错误码推导（`src/policy_api/errors.py` 的 `STATUS_BY_CODE`），调用方不能自定义。

| 场景 | 状态码 | 错误码 |
| --- | --- | --- |
| 未认证 / 令牌过期 | 401 | `unauthenticated` / `token_expired` |
| 越权（令牌范围、项目、指标端点） | 403 | `token_scope_mismatch` / `project_not_allowed` / `metrics_forbidden` |
| 请求体过大 | 413 | `body_too_large` |
| 幂等键冲突 | 409 | `idempotency_key_conflict` |
| 限流 | 429 | `rate_limited` |
| 超时 | 504 | `evaluate_timeout` / `retrieve_timeout` / `validate_timeout` |
| 请求级预算被拒 / 服务繁忙 | 503 | `request_budget_exceeded` / `policy_busy` |
| 依赖不可用 | 503 | `rule_set_unavailable` / `knowledge_unavailable` / `validator_unavailable` / `evidence_unavailable` / `idempotency_unavailable` / `audit_unavailable` |
| 未知版本 / 非法请求体 | 400 | `schema_version_missing` / `schema_version_unknown` / `body_invalid` |

**没有任何一条路径默认 allow**：超时、不可达、规则集读不出来都只会更严。

## 9. LangGraph 编排（Phase 8）


- 恢复语义：规则集或索引变了会清掉旧 trace 与旧验证结果、回到检索节点重评（**不沿用旧 allow**）；
  工具 schema 变了旧审批作废；协议世代变了直接拒绝恢复；"开工未结算"→ `side_effect_unknown` 交给人。

## 12. 常见问题（FAQ，全部 Phase）

| 现象 | 原因与处理 |
| --- | --- |
| `ModuleNotFoundError: policy` | 没设 `$env:PYTHONPATH = "src"`（或用 `uv run`） |
| 正例也退出 1，提示 `tool.ruff@1.0 unavailable` | 本机没有 Ruff；`python -m validators.cli probe` 自查，或（有意）改 `validation/validators.yaml` |
| 第二次 `execute` 退出 1，提示 `action_replay` | 这是**正确**行为：`action_id` 是幂等键。换 `action_id` 或先 `tools/cleanup.py` |
| 规则明明写了却不生效 | 看 `skipped_rules` 的维度原因；`--language ""`（语言未知）会跳过语言相关规则；`write` 映射成 `operation=create` |
| 改了注册表 / manifest 后工具或 Adapter 不可用 | 必须重新审核：`enforcement.cli registry --approve` / `adapters.cli approve` |
| `retrieval.cli query` 退出 1 | "没有结果"是显式状态（`no_results`），不是错误；换个查询或确认语料已索引 |
| `dsh_sandbox_loop.py` 退出 0 但什么都没跑 | 环境跳过（无 dsh 或沙箱禁止管道 stdio）；输出里有 `reason` 与 `reproduce` |
| `retrieval.cli verify` 退出 1 | 镜像哈希 / 字节数漂移，或条目不在 manifest 中；先看输出的漂移清单再决定重爬还是修清单 |
| CI 在 GitHub 侧没有分支保护 | 这是**刻意**的：单人仓库把检查前移到本机（pre-push 钩子），理由是边际价值低于成本 |
| `.tmp/` 越来越大 | 它是构建产物与会话产物，随时 `python tools/cleanup.py` |
