## 维护方式

```powershell
# 改文档：过一遍文本规范门禁（UTF-8 / LF / 行尾空白 / 结尾换行）
python tools/check_text_conventions.py

# 文风自检（概括句 / 长句 / 术语墙 / 连续无标点）
python tools/check_arch_style.py
```

**硬规则：改文 / 改口径必须两处同改**（口径表：[术语与口径.md](术语与口径.md)）

两处指**文**与**口径表**：**文** = 本目录各份 `.md`；**口径表** = `术语与口径.md` §0–§7。
只改一处会让文与口径再次脱钩——编号、层名、数字都是这样脱钩的。

```powershell
# 1) 层名自检：六层规范名必须同时出现在 功能清单 / 口径表（六个层名各查一次）
Select-String -Path docs/project/architecture/功能清单.md, `
    docs/project/architecture/术语与口径.md -Pattern '④ 能力层', '⑥ 证据与门禁'

# 2) 数字口径自检：改完数字后回口径表 §5 逐条复跑命令（例：闭环脚本数）
(Get-ChildItem tools/*_loop.py).Count
```

**改文风先改口径表 §7**（概括 + 精确锚点的阈值都在那里），再改文稿。

**四条容易写错的地方**：

1. 本目录写的是**当前代码实际做到的事**：改代码后对照 `src/`、`policies/`、`registry/`、
   `validation/`、`adapters/`、`api/` 的实际内容更新它，别把计划写成现状；
2. 文档里的**用例数、条目数、工具数**这类数字会过期，改完顺手核对一遍
   （`python -m pytest -q`、`python -m retrieval.cli verify`、`python -m enforcement.cli registry --list`）；
   **数字的口径与实测命令只认 [术语与口径.md](术语与口径.md) §5**；
3. **三套编号不许互相替代**：转化链路写“台阶 N”，实施批次写“Phase N”，
   门禁条件写“①②③”（定义在 [规则文档转化为规则.md](规则文档转化为规则.md)）——
   对照表见 [术语与口径.md](术语与口径.md) §2；
4. 不要把“计划做的”写成“已经做的”。仓库的惯例是：**没做的写进“明确没有做”那一节**。
