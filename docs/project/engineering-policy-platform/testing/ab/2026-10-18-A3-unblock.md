### 4.1 命令族（预注册；"族"= 注册表白名单的一条 pattern，不是"条子"）

### 4.2 一张条子覆盖两族（**当前 CLI 的现实**）

- `approval: required` 的工具是 `exec.pwsh`（`tool-registry.local.yaml#L131-L142`），两族共用同一个 `tool_id`。
- 当前 `approve` 对**同一 tool_id 的记录是取代不是叠加**（`src/enforcement/cli.py#L693-L712`：`item.tool_id == record.tool_id` 即被替换）——因此**不能**用两次 `approve` 分别签 F1/F2（第二次会把第一次抹掉；Governance 现有两条 pwsh 记录是旧 CLI 时代的形状，不要照抄）。
- 做法：**一条条子，`command` 用一个 alternation 同时覆盖两族**：

```
^(python -m pytest( .*)?|python tools/[A-Za-z0-9_./-]+[.]py( .*)?)$
```

（`verify_approval` 用 `re.fullmatch` 逐参数整串匹配：`src/enforcement/approvals.py#L556-L567`。）

## 9 探针更正（2026-10-18，A3 单动作探针）

> 依据：[readings/2026-10-18-A3-single-action-probe.md](../../readings/2026-10-18-A3-single-action-probe.md)（8 次真实 dsh headless 会话，全部 exit 0，全部产生真实 Hook 判定记录）。本节只更正/补强本文，不重写已成立的部分。

1. **U1 判据更正（D1）**：§3.5 的 U1 判据「读审计里 session_scope=in_scope / session_cwd=. / project_root=.」按原文读不到——in_scope 的 governed 记录**根本不写**这三个键（它们只在 scope fallback 记录里出现）。替代证据是三件：① 审计里 `governed=true` 的受治 PreToolUse 记录；② 会话日志 `session.header.cwd`（= dsh 启动 cwd）；③ 差分探针：同一提议内容在受治树下被执行、文件哈希真变。详见探针读数 §5.5。
2. **启动 cwd 硬约束（D2）**：受治臂必须以**任务树根**为 cwd 启动。实测在子目录/项目外启动时，目标归一化按 `projectDir`、工具真实写入按会话 cwd，**判的不是同一个文件**（`post_inconsistent` exit 2 / `evidence_unavailable`）；这一条比 U1 原文更硬，A3 正式跑前必须写进 run-manifest。
3. **审计混协议（D5）**：`audit.jsonl` 同时含 Hook 判定（`audit_schema_version` 1.3）与 Phase 4 执行链记录（`stage`/`sequence`），① 的 audit→actions 装配器必须按 `audit_schema_version` 过滤，不能按「有 action_id 就当判定」。
4. **U2 限定**：Hook 之前不要求审批（三份宿主事件均为 workspace-write / approval=ask，无 approval/* 请求）；**Hook 放行之后宿主是否仍要求审批未核实**（唯一触发是 `exec.pwsh`，注册表 `approval: required`，代理不得签条子）。使用者签 4.4 的条子后补一条 U2-b 探针。
5. **N-7/N-8/N-9 已裁定**：见 06 `P-A3-003`（A3 不以 B1 为前置；受治臂权限模式须与真实入口一致并记 `reading_context.host.sandbox`；装配器探针阶段放 `.tmp/a3b/`、复用再升格 `tools/`）。
6. **新发现的读数口径风险**：受治理的 PreToolUse 被阻断后宿主仍会发 PostToolUse（`post_error` 包裹原始理由，D6）——② 读 `PreToolUse` 的 decision，不读模型自述。
