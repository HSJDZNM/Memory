## 4. 额外观测（未预注册，但比这一级本身更重要）

### 4.1 命令这条路**已经在真机走通**（L1 的问题被提前回答）

会话里模型自己发起了一次 `pwsh`（`action_id=…call_00_JA1PRLfCehm1Ghx2fsJF0717:ptc:1`，23:41:22Z）：

- 审计：`reason_code=enforcement_allow`、`grant_id=grant-759cd54cb4ff4738`、`grant_expires_at` 有值；
- 台账：同一条 `action_id` 有 **6 条**记录 `claim / approval_used / grant / pre_decision / pre_state / execution`，其中 `kind=execution` 在 23:41:26Z；
- `pre_state` 里的**真实参数**：`command="python -m pytest -q"`、`description="Run project test suite"`——**正好两格**，与签名的两格一致；
- 会话侧：工具返回 `exitCode=0`、`3 passed`（模型自己的结论句：「Tests pass: 3 passed」）。

⇒ **使用者最想要的那条（自动跑测试、不用逐条点头）在受治 GUI 里成立**：放行 → 发凭据 → 真的执行 → 测试通过。
⇒ 这同时是本项目第一次观测到 `exec.pwsh` 的**发凭据支路**（`enforcement_allow` + `grant_id`，`executed=false`）——
证实了研讨里那条判据陷阱：**用 `executed=true` 当「命令跑了」的判据会把这次成功判成失败**。

**仍未证明**：形状固定性。历史读数里同一会话内出现过 2–3 种格；这一次恰好是两格。
下次模型带上 `workdir` / `timeoutMs` 时，两格签名会被拒（那是摩擦，不是治理）。
