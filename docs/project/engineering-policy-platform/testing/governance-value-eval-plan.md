# 规范治理价值测试方案（v0.1 · 提案，未实施）

> **这份文件是什么**：把“本项目的规范治理价值”拆成**可被证伪的判据**与**可执行的外部评测**，
> 并给出落点、门槛、成本与“如果只做一件事”的顺序。数据集登记在 [eval-datasets.yaml](eval-datasets.yaml)。
>
> **它不是什么**：不是宣传材料；**任何一条价值结论都不允许拿平台自己的判定当标签**（自证循环）；
> 也不是“跑一遍公开 benchmark 报个分数”——公开 benchmark 大多测**模型**，本项目是**门禁型平台**，
> 它要回答的是另外三个问题（见第 2 节）。
>
> **状态口径**：`【已核验】`= 2026-10-07 在本机用 `gh api` / HuggingFace API / 仓内文件核验过；
> `【实测】`= 取到 **pin 住的**上游 revision 之后跑出来的数字（§4.5 / §4.5.1，带样本量 N 与命令）；
> `【自洽性检查】`= 用平台自己的读数或证据工具自查（R1：**不进价值结论**）；
> `【待核验】`= 只从搜索结果看到，存在性、规模或许可尚未确认；`【提案】`= 本文给出的数字与门槛，
> **尚未标定**，不得当既有读数引用。
> `【判定】`= §4.7 给出的「能不能用 / 用在哪一层」的结论：带推理链、证据与反面清单，
> **不是读数、也不是门槛**（2026-10-07 新增）。

## 0 先定义“价值”：三条主张与它们的证伪判据

| 主张 | 说人话 | 判据（可证伪） | 现有读数 |
| --- | --- | --- | --- |
| A 判定可信 | 拦住一个动作时，理由是**对**的，而且能说清凭什么 | 第三方标注语料上 error 级规则的精确率下限；未命中的项**没有一条**是“既没报也没说明” | **没有数据**（见第 1 节） |
| B 挡得住坏动作 | 未知 / 无证据 / 越界 / 重放，一律不放行 | 故障注入矩阵上 allow 泄漏 = 0；同输入重复判定逐字节相同 | 有单元/契约用例，**无外部对抗语料** |
| C 摩擦可承受 | 好代码不被无谓拦下，拦截可定位、可修复 | 成熟代码上的阻断率与每千行诊断数；A/B 下完成率损失 | 一次 192 文件 / 63,645 行读数：block 31.8%（其中 63.9% 只由 F401 造成） |

一句话：**这个平台稀缺的地方不在“能查”，在“拦住时理由对、拦不住时说出来、坏掉时不放行”。**
测试方案因此必须把**精确率**与**失败关闭**当主角，而不是把规则条数或命中数当成绩。

## 1 现状与缺口（全部是仓内已记录的读数）

已有的评测资产：

- 检索固定评测集：7 查询 + 门槛 + `baseline-v3.json`，进 CI 硬门禁（`tools/retrieval_eval.py`）；
- 规则级正反例夹具：由镜像文档提炼的 38 条规则各一对 `good.py` / `bad.py`，走**真实验证器流水线**（`tests/integration/test_rule_corpus.py`）；

- 受控执行 / 验证器 / API / 编排四个闭环脚本；
- 自证探针 `tools/governance_gap_probe.py` 与仪器自证（R-h）。

缺口（照抄仓内自己的结论，不改口径）：

1. `docs/project/reviews/open-code-review-对比报告.md` 第 1.4 / 6 节：**“没有任何一侧有‘规则/评论准确率’数据”**；
   同文第 1.3 节：检索命中率不等于评审质量。
2. `docs/project/architecture/规则转化覆盖报告.md` 第 10.4 节（实测，不是估计）：
   - 本仓库自身 192 个 Python 文件 / 63,645 行 → `block` 61 个（31.8%），其中 **39 个（63.9%）完全来自 `STYLE-002`（F401）**；
   - 22 个文件带 SEC 规则 error 命中，逐条打开源码核对后 **16 个是启发式误报**、6 个情境不符或刻意为之；
   - 第三方 680 文件 / 227,642 行 → 6,557 条诊断，**86.4% 是行宽与 docstring 风格**，全部 S 码合计 29 条（0.44%）。
3. 结论：**精确率、误报代价、真实缺陷检出率、摩擦成本，四项都没有被测量过**——这正是本方案要补的四格，
   而且补的方法必须能被别人重跑。

**第一次实测（2026-10-07，L1 已跑通；不改变上面四格的性质）**：`tools/governance_eval.py --suite fidelity` 的读数落在
`evaluation/results/fidelity-<revision>.json`：L1b（平台判定 vs **同一次** ruff）TP 499 / FP 0 / FN 0、P = R = 1.0、
GV-03 = 1.0、GV-04 = 0；L1a（原始 ruff 诊断 vs 上游标注）precision 0.2286、行级 recall 0.1013，**只报告、不进门槛**；
本仓库扫描 262 文件 / 115,249 行 / block 62（23.7%）；43 条规则的粒度三档 = 行级 21 + 作用域级 5 + 定义级 3 + 无标签 14
（读数里的 `tier_counts`；其中行级 21 + 作用域级 5 = **有位置标注 26**，与 §4.5 的三档口径一致），
其中 16 条 `insufficient_sample`、**只有 5 条能进门槛**；负例控制 89 个 `Okay` 作用域；**P1 判不了**（语料 n = 3，
本仓库侧按 R1 不可算）。这一轮的 262 文件 / 115,249 行**不是**第 2 条那 192 文件 / 63,645 行那一批，
跨读数不许直接比较（§6.4 的 `reading_context` 纪律）。这一轮补的是 **L1 保真度**，它**不关闭**上面第 3 条的「精确率」那一格——
L1 全绿只说明平台忠实转述了它声明的证据工具（§2 的 R2），判据对象仍不是「这条诊断值不值得报」。

## 2 三层证据：保真度 ≠ 有效性 ≠ 价值（防自证循环的地基）

| 层 | 问题 | oracle（标签从哪来） | 能证明什么 | **不能**证明什么 |
| --- | --- | --- | --- | --- |
| L1 实现保真度 | 平台的判定与它声明的证据工具口径一致吗 | 工具**自己的**标注测试集（Bandit / pycodestyle / pylint / semgrep） | 归属、分级、聚合、证据传递没有走样 | 这条诊断是否值得报 |
| L2 判定有效性 | 报出来的问题，人会不会同意 | 人工标注抽样（Cohen's κ）；真实 CVE 修复提交（GHSA / OSV） | 在抽样范围内“报得准” | 全量准确率（抽样误差必须写出来） |
| L3 治理价值 | 有治理和没治理，结果有差别吗 | 独立扫描器 + 仓库测试通过与否（外部 oracle）+ A/B | 值不值得装 | 单次实验之外的外推 |

三条纪律：

- **R1 不许自证**：任何“平台有效”的结论，其标签不得来自平台自己的 Decision；用平台读数的地方一律标注为“自洽性检查”，不进价值结论。
- **R2 三层不许互相顶替**：L1 全绿不等于 L2（可能整套规则一起报错东西）；L2 好也不等于 L3（可能代价大于收益）。
- **R3 预注册**：门槛在跑之前写进数据文件（`evaluation/thresholds.yaml`），跑完只允许“如实记录 + 显式重记基线”，
  不允许调参到好看——与 `retrieval_eval.py` 的 `--record` 同型。

**L2 的 oracle 里没有 AACR-Bench，也没有任何「评论级」数据集**（2026-10-07 判定，论证见 §4.7）：
它标的是「这条**评论**是否正确」，我们产的是「这条**规则**在这一点命中」，两个命题互不蕴含；
把它当 L2 的标签源是**跨层顶替（R2）**，自己写一张 rule ↔ comment 映射再算一致率则是**自证（R1）**
（与 §4.5 记的 pylint / semgrep「与平台码集交集为 0、等价关系人工声明 → 不计入 GV-01 / GV-02」同型）。
它在我们这里的合法位置只有一个：**L2 的抽样框**（§4.7.3）。

## 3 指标字典（每条都要能机器算出来）

| ID | 指标 | 定义 | 数据来源 | 门槛【提案】 |
| --- | --- | --- | --- | --- |
| GV-01 | 规则精确率 | 行级 TP/(TP+FP)，按 `rule_id` 分组，error 与 warning 分开 | **L1b**（平台判定 vs **同一次**原始 ruff 诊断） | error 级 ≥ 0.90，整体 ≥ 0.80 |
| GV-02 | 规则召回率 | 行级 TP/(TP+FN)，按 `rule_id` 分组 | **L1b**（同上） | 每条已启用规则 ≥ 0.80 |
| GV-03 | 归属准确率 | 命中行的 `rule_id` 与标注码的映射正确率 | **L1b**（同上） | 1.00（错归属 = 公示了错误的理由） |
| GV-04 | 静默漏报率 | **结构化比对**：标注为阳性的目标，在 Decision 的 `violations` / `skipped_rules` / `check_volume.skipped_by_reason` / `language_coverage` 四个**结构化字段**里都找不到该（规则, 目标）的处置记录，才算静默（**不解析 reasons 文本**） | L1b 语料 + 平台载荷 | **0（必须）** |
| GV-05 | 覆盖诚实度 | CWE Top 25 ∩ 能力内 vs 显式声明不覆盖 | CWE Top 25 + Bandit 插件 CWE | `silently_uncovered` = 0 |
| GV-06 | 真实缺陷检出 | 带 CWE 标注的真实修复提交在 pre-fix 树上是否命中 | GHSA / OSV | 只报告（先看样本量） |
| GV-07 | 攻击阻断召回 | 标注为“应当拒绝”的 agent 任务里被拒绝的比例（block ∪ `capability_unavailable`） | AgentDojo / InjecAgent / AgentHarm | ≥ 0.95【提案】 |
| GV-08 | 良性阻断率 | 标注为良性的任务与成熟代码上的 block 比例 | M4 + M8 语料 | 报告值 + 回归不劣化 |
| GV-09 | 失败关闭泄漏 | 故障注入下返回 allow 的次数 | 故障矩阵 | **0（必须）** |
| GV-10 | 判定决定性 | 同输入 N 次重复 + 异机（CI 与本机）逐字节相同 | 全部 | 1.00 |
| GV-11 | 溯源完整率 | 命中项能解析回 `source.path` + `heading_path` 的 chunk 的比例 | 规则 `rule_sources` | 1.00 |
| GV-12 | 检索质量 | `hit@k` / `support@k` / precision / recall | 现有评测集 + CUAD / LexGLUE | 沿用 `baseline-v3`，**不放宽** |
| GV-13 | 摩擦成本 | 每千行诊断数、阻断率、单次判定延迟 p50/p95 | 良性语料 | 报告值 + 不劣化 |
| GV-14 | A/B 效应 | 违规密度差（独立扫描器）、任务成功率差、人工干预次数差 | SWE-bench 子集 | 见 6.5【提案】 |
| GV-15 | 人评一致性 | 抽样上平台 finding 与人工标注的 Cohen's κ | 抽样标注 | ≥ 0.6【提案，需先做标注手册】 |
| GV-16 | 位置重合计数（描述性，**不是**精确率） | 分子按评论标签分列（`c1` = 落在 `label=1` 评论区间内的 finding 数、`c0` = 落在 `label=0` 区间内的）；**分母 = 平台在 `pr_target_commit` 那棵树上报出的全部 finding**（错位项照留，不删） | AACR-Bench（W9，口径见 §4.7.3） | **无门槛**：只报告 (c1, c0, n) 三个原始计数与比值；**禁止**换算成精确率 / 召回率 / 一致率 |

每条指标落地时必须写清三件事：**分母是什么、行号怎么匹配、口径不同怎么记**（第 5 节各工作包）。只给一个数字不算读数。

**GV-16 的口径先写死再跑**（它是唯一一条「读出来一定会被误读成精确率」的指标）：分母是该树上平台报出的全部 finding；
匹配口径 = 同 `path`、同 `side`、finding 行落在评论 `[from_line, to_line]` 之内，**容差必须显式写出**；
分子按评论标签分列、**不许合并成一个数**。它的产出者（W9）**不许**给它设门槛、也不许把它写进 §0 三条主张的「现有读数」——
它既不是 L1（标签不是证据工具的），也不是 L2（标签不是人对平台 finding 的判断）。

**GV-01 / GV-02 / GV-03 钉在 L1b 那一跳**（平台归属 / 分级 / 聚合 vs **同一次**原始 `ruff` 诊断）：
它们测的是「平台有没有忠实转述它自己声明要用的证据工具」。**L1a**（原始 ruff 诊断 vs 上游标注）
度量的是证据工具与上游标注的差，**只报告、不进这三条指标、也不许拿来解释或掩盖 L1b 的差值**。
**GV-04 的判据是结构化比对**：读 `violations` / `skipped_rules` / `check_volume.skipped_by_reason` /
`language_coverage` 四个字段里有没有该（规则, 目标）的处置记录——**不解析 reasons 文本**
（文本会随措辞变化，正则匹配会统计到「恰好含某个词」而不是「确实说了」）。

#### 4.5.3 片段物化通道（task-6，2026-10-07 实测）

**接口**（加性导出；不动 `eval_corpus.py`、不加数据集 id、不加 lock）：
`tools/eval_corpus_extra.py` 的 `materialize_snippets(dataset_id, *, corpus_root, out_root)`。
产物**只写 `out_root`**（默认 `.tmp/eval-corpora-materialized/<id>@<rev>/`），**绝不写锁定语料目录**——
往 `<corpus_root>/<id>@<rev>/` 里加文件会让 `eval_corpus.py --verify` 变红。
`MaterializationResult` 带 files / annotations / file_expectations / file_sources / accepted / rejected /
reject_reasons / acceptance_rate / oracle。**它不经过 `load_annotations()`**：harness 要显式调它。

**oracle 口径（机器可读字段 `oracle = "file_level_code_set"`）**：文件级**码集合**比对，不是行级——
集合里的码报出来了 = 命中、没报 = 未命中；片段上出现的**其它**诊断进 `noise` 桶、**绝不算 FP**；
只有对**受测码**的期望集合为空（含显式空期望，例如 `assert results == []`）的文件上报出受测码才算 FP。
受测码 = 该语料的期望码集合 ∩ `policies/**` 声明的码（由调用方推，本模块不写第二份映射）。
全部注解 `line = 0`：片段内的相对行号**不进** Annotation。

### 4.6 4 条非 style_lint 规则的替代 oracle（没有第三方行级标注时怎么办）

这 4 条规则（ARCH-001 / DOC-001 / TESTING-001 / TESTING-002）**没有**可用的第三方标注：它们的 scope 带
`layer` 或 `operation`，语料本身给不出上下文（必须由 harness 显式构造），而公开语料里也没有人为它们标过
「这一行该报 / 不该报」。正确做法不是"跳过"，而是换一个**能被证伪的替代 oracle**——并且把
「能证明什么 / 不能证明什么」写在每一格旁边。

| 规则 | 替代 oracle | 能证明什么 | **不能**证明什么 |
| --- | --- | --- | --- |
| ARCH-001（`forbidden_dependency`，scope 带 `layer: controller`） | **自建变异语料 + 独立实现对照**：在一棵固定的夹具树上，把「控制器 → 领域层」的依赖逐条变异进去（一次只改一处），用独立实现（如 `import-linter` 的层契约，或标准库 `ast` 写的 import 图）算出「谁依赖了谁」；期望：每一处变异都必须命中 ARCH-001，未变异处不命中 | 能：依赖提取口径与独立实现**在同一棵树上**一致；变异体逐条可定位到规则 | **不能**证明：`layer` 声明的层划分是对的（那是配置问题）；也不能证明「这条依赖真的有害」——它只证明「按声明的层，这条边越界了」 |
| DOC-001（`missing_docstring`，内置 `py.docstring`，不用外部工具） | **pydocstyle D1xx 差分对照**：对同一批目标跑 pydocstyle（D1xx 家族）与本平台的内置验证器，逐目标比对 | 能：内置验证器的「哪些对象缺 docstring」与一个成熟实现**逐目标可比** | **不能**算进 GV-01 / GV-02：两者的等价关系是**人工声明**的（D100/D101/D103 与 targets=module/class/function 不是同一口径，含 `include_private` 差异），所以它只能作差分对照，不进精确率 / 召回率的分母 |
| TESTING-001（`missing_tests`）+ TESTING-002（`failing_tests`） | **buggy-fixed + 测试的仓库语料**：BugsInPy / Defects4J / SWE-bench 这类「有失败测试的真实修复」语料，取 pre-fix 树 → 期望 TESTING-001/002 至少把"这里没有测试 / 测试不过"说出来 | 能：在**外部成功判据**（仓库测试）明确为假时，平台有没有把这件事说出来——这是失败关闭面的正例 | **不能**证明：测试**写得对不对**（覆盖不足、断言空转的测试在两边都算"有测试"）；也不能用任务成功率当平台的检出率，那是 §7 W7 的 A/B 要回答的另一个问题 |

三条一起的纪律：**替代 oracle 只进它自己那一格**。上面任何一行的读数都不许回填到 GV-01 / GV-02，
因为它们的标签不是第三方对这个平台码的行级标注（R1 不许自证、R2 三层不许互相顶替）。

#### 4.7.3 AACR-Bench 能不能当 L2（本次核心）

**结论先行：不能当 L2——它给不出 TP / FP / FN 里的任何一个。** 三种对齐情形逐条如下。

**(a) 我们的 finding 落在 `label=0` 的评论位置上 → 不能算 FP。**

1. `label=0` 说的是「**这条评论**不对」，不是「**这一点**没有缺陷」。一条被专家判错的评论可以指向一个真实存在的问题（只是说错了原因）；
   一条被判对的评论也可能什么都没说到。两个命题互不蕴含（核验文档 §6.3 第 3 条：「缺判定对象的同一性」）。
2. **位置重合不等于判据重合——实测例证**（**【自洽性检查】，R1：不进任何价值结论**）。把 PR#1482 的
   `browser_use/browser/browser.py` @ `0b21e50ca640581ecd46990475c8b223eaa05045` 放进桩工作区，
   跑 `python -m policy.check`（`PYTHONPATH=src`）：**31 条 violation**，其中 **STYLE-001（E501）落在第 220 行与第 277 行**——
   这两行正是 `label=0` 的评论位置（那条评论说「用字典格式化降低可读性」/「常量应硬编码以便 grep」）。
   我们的 E501 是**忠实报告**一条已声明规则（第 220 行 102 字符 > `validation/ruff.toml` 的 `line-length = 100`），
   与那条被否掉的评论**毫无关系**。把这 2 条记成 FP，就是把「理由对、位置撞上」记成了误报。
3. 若要把这种重合当作 FP，先得写下「评论为错 ⇒ 我们的判定为错」这条等价关系——那是**我们声明的**，
   与 §4.5 里 pylint / semgrep 的处境同型（「等价关系是人工声明的，不计入 GV-01 / GV-02」）；用它得出价值结论就是**自证（R1）**。
4. 而且「落在同一条评论里」这件事本身还依赖一个没人写下来的裁定：评论行号属于哪棵树——见 (c) 第 4 条与 §4.7.4。

**(b) 落在 `label=1` 上 → 不能算 TP。** 同上对称：`label=1` 说「这条评论对」，不说「我们这条规则该报」。
实测例证（同一次运行）：`label=1` 的评论在 82–83 行（内容是 `use to when` 的**拼写**错误），而我们的 E501 落在第 84、85 行——
位置相邻、判据无关。把它算 TP，等于用一条拼写评论去认证一条行宽诊断。
（同样的反例还有 290–292 行：那条评论讲的是 `int | None` 可能触发 `TypeError`，是本仓**能力外**的一类——
43 条规则里 0 条 `type_check`，`tool.mypy` 也没装，见 §4.5 的运行前提。）

**(c) 错位**（我们报的它没评论 / 它标的我们没报）→ **既不能算 FN 也不能算 FP**，四条理由：

1. **缺失标签不是负标签。** 那 2145 条是「被保留下来的评论」；构造过程只从「有内联评论的 PR」里取样
   （核验文档 §3：论文自己说人工评审会漏，才要用 6 个模型补覆盖），**没有任何一处为「这里没有缺陷」做过采样**。
   所以「我们报了、它没评论」没有任何 FP 证据；「它评了、我们没报」只是一个**未标注**候选，不是 FN。
2. **真值自己承认不完备**：论文结论段原话是 `constructing a fully comprehensive Ground Truth remains a formidable challenge`
   （OCR 文档 §7.2 引用）；open-code-review 也自述 Recall 是**故意**用来换精确率的（OCR 文档 §7.2）。
   拿一份自认不完备的真值去数漏报，会把「数据集没覆盖」记成「平台漏报」。
3. **我们的产出面受规则集约束**：43/43 条规则 `language: python`（§9），落在规则集外的「缺陷」是**能力外**，
   按 §4.5 的口径既不算 TP 也不算 FN——而 AACR 的真值里大量是这类项（(b) 的 290–292 行即一例）。
4. **位置连接本身要先裁定基准**：实测 3 个 PR 里 **2 个**的 `pr_source_commit` / `pr_target_commit` 在 GitHub 上是 `diverged`，
   「source = base、target = head」这条上游读法不成立（§4.7.4）。基准没定死之前，错位连「对齐没对齐」都判断不了。

**所以它能给的读数只有一个，而且是描述性的**（口径与分母先写死，防止被读成精确率）：

- 命名：**GV-16 位置重合计数**（§3），**不叫精确率**；
- 分母 `n` = 平台在 `pr_target_commit` 这棵树上报出的**全部** finding（错位项照留、不删——删了就变成「只挑好看的」）；
- 分子按标签分两列：`c1` = 落在 `label=1` 评论区间内的 finding 数，`c0` = 落在 `label=0` 区间内的；
  匹配 = 同 `path`、同 `side`、行落在 `[from_line, to_line]` 内，**容差必须写出来**（本次演示用 ±3 行：31 条里 4 条命中 = `c1` 2 / `c0` 2）；
- 读数形式：**`(c1, c0, n)` 三个原始计数 + 比值**，无门槛、不进判定，必须带 `reading_context`（哪棵树 = 哪个 commit、哪个环境、哪套声明）；
- **禁止**把它换算成「精确率下界」：下界要成立，先得证明「位置重合 ⇒ 该 finding 为真」，而这条蕴含没有外部依据（(a) 第 3 条）。
  只有当**第三方**给出这条蕴含时，`c1 / n` 才是一个下界；在那之前它只是一个计数。

**它真正能当的是什么：L2 的抽样框（sampling frame）。** 把 `c1` 那一叠（专家确认过的评论位置上的平台 finding）交给**人工**独立标注
（GV-15 的口径：盲化、不告诉标注者 `rule_id` / `severity`、必须报 κ），那才产生 L2 标签；AACR 负责**选样**，不负责**给标签**。两条必须写下来的偏置：

1. 从「评论覆盖到的位置」抽样，**只能回答精确率方向的问题**，回答不了召回——框外的点不在样本里，而评论自己也漏（核验文档 §3）；
2. 框是被判过对错的集合，标注者看到的 finding 分布**不是平台上真实的分布**（这一点必须和读数一起写）。

**唯一能让「不能当 L2」被推翻的路径（证伪条件）**：有人给出一个**不由我们声明**的连接键——例如 `note` 里直接写规则码 / CWE / 标准条款号。
本次实测这条路是断的：2145 条 `note` 上 CWE、Bandit `S###`、pydocstyle `D###`、`OWASP`、`bandit`、`pycodestyle`、`PEP 8`
命中**全为 0**（核验文档 §7.3；我自己复算了一遍，并加了一条本仓规则 ID 形态 `(SEC|STYLE|DOC|ARCH|TESTING)-\d{3}`，同样 0 命中）。
一旦出现这样的键，本节结论作废，W9 可以升级为 L2 评测。

#### 4.7.5 没有资深工程师时，该抄它哪几条（对照 OCR 文档 §7.1 的六条替代）

| # | 它的替代 | 我们能用的 | 我们不能用的 | 用了会不会变成自证 |

| ① | 把资深工程师用在**数据集**上，而不是每个 PR 上 | **形状**：一次性、可复用、可被外部引用的判断替代「每个 PR 多人看」 | **人**：我们没有资深工程师，也没有「80 人 × 三轮」；连 1–3 人的常设评审都没有（单人仓库） | 不会——标签由人给，不是平台给的。但必须披露标注者资质与人数，并**报 κ**（它没报，OCR 文档 §4.2） |

| ③ | 端到端评测集当**发版闸门** | **形状**：固定评测集 + 预注册门槛 + 基线重记（我们已经比它强：`thresholds.yaml` 把门槛写死，它连「pass 是什么」都没定义，OCR 文档 §5.2） | 「用 AACR-Bench 当那个闸门」——§4.7.3 已判定它算不出 P/R | 不会（闸门跑的是 L1b）；但**不许**把它当 L2 闸门 |

**合起来的一句话**：OCR 文档那六条替代能抄的是**形状**，抄不到的是**人**。
在「没有资深工程师、没有生产遥测」这两个约束下，L2 只剩一条可走的路——**外部事实优先**：
真实修复提交（GHSA / OSV，§5 W3 / GV-06）、**独立实现**的差分对照（§4.6，且只进它自己那一格）、
仓库测试这个外部成功判据（§5 W7）。人造标注只能做成**小样本 + 盲化 + 报 κ**（GV-15），
而**不能**用一份不同构的公开数据集把 L2 那一格「填满」——那正是本次要挡住的结论。

#### 4.7.6 风险与反面清单：照着做会得出错误结论的 8 条路径

1. **把评论级标签当 finding 级标签** → 会把第 220 / 277 行那种**忠实**的 E501 记成误报（§4.7.3 的实测）。
2. **把错位当漏报** → 把「能力外」与「数据集没覆盖」记成 FN，同时违反 §4.5 的能力外口径与核验文档 §3 的自认不完备。
3. **把 HF 快照当上游当前版** → 恰好 1 条记录（dbeaver#37564）在两侧标签相反（核验文档 §6.2 缺陷 A）；不裁定就引用，等于引用了一个上游自己改过的标签。
4. **把「一致率高」读成「规则对」** → 判据对象不同、且没有连接键（核验文档 §7.4）；映射表若由我们写，就是自证。
5. **用 LLM 做语义匹配来「造连接键」** → 上游 `judge.py` 在没有 `JUDGE_API_KEY` 时静默退回 `difflib`（`sequence_ratio ≥ 0.4` 或 `jaccard ≥ 0.3`），单条裁判失败被当作「不相似」（核验文档 §4.4）。我们这条纪律是**失败关闭**，裁判不可用不许降级成结论。
6. **把 41.15 GiB 的全量克隆当成唯一取数路线** → 最小子集走 raw + compare 只要 ≈ 2.4 MiB（§4.7.4）。反过来，照全量 clone 做会得出「贵到不做」的结论，而那是**路线**造成的，不是数据造成的；本机 clone 路线甚至不可复现（msys 管道被拒）。
7. **把流程描述当成可靠性证据** → 「双盲双标注 + 专家组裁决」是流程，论文**没有任何一致性系数**（核验文档 §4.1 / OCR 文档 §4.2）；照抄流程而不报 κ，等于把流程当证据。
8. **把 README 的 `1,505 annotated ground-truth issues` 读成 1,505 个缺陷** → 论文口径是 1,505 条**评审评论**（OCR 文档 §3 已校正）；读成缺陷数会系统性高估真值规模。

- 故障矩阵：验证器缺失 / 版本不符 / 超时 / 崩溃 / 输出非法 / 索引不可用 / 注册表哈希漂移 / 审批过期 /
  审批重放 / 参数改一个字符 / 未知 schema 版本 / 跨租户 / 观测日志不可写。
- 期望：`allow` 泄漏 = 0；每一次拒绝都要给出“改成什么形态就能过”（第 50 条）。
- 仪器纪律：新检查**必须能红**（照第 45 / 53 条：在 `git archive HEAD` 的副本上做一次显式变异 → 变红 → 撤回 → 变绿），
  做不到就写“这条检查覆盖不到”。

### W6 检索与规范溯源（离线 + 外部语料）

- 现有 7 查询是**回归门槛**，不放宽；新增 CUAD / LexGLUE 作**外部有效性**：
  条款级 ground truth → 检索到的 chunk 是否覆盖该条款、`heading_path` 是否指向原文位置。
- 判据：GV-11 = 1.00；GV-12 不劣于 `baseline-v3`。

### W7 价值 A/B（成本最高，最后做）

- 两臂：治理开 / 治理关，同一 agent、同一任务集（SWE-bench Verified 固定子集，例如 50 条；或 BugsInPy）。
- 结局变量：(a) 违规密度（**独立扫描器**，不是平台自己）、(b) 任务成功（仓库测试通过，外部 oracle）、
  (c) 摩擦（被拦次数、重试、墙钟）、(d) 升级人工次数。
- 预注册 MDE 与样本量；不足则如实写“未达功效”，而不是把不显著读成“没坏处”。
- 证伪：违规密度没降且成功率下降 > 10% → 该场景下治理是负价值。【提案】

### W8 摩擦与成本（离线，复用已有两份基线）

- 良性语料：本仓库自身（192 文件 / 63,645 行）+ 第三方 680 文件 / 227,642 行。
  **注意**：第 10.4 节的第二次基线没有写明取用路径，复现时必须补 `reading_context`（哪棵树、哪个环境、哪套声明），
  否则“同一份读数”无法被第二个人重放。
- 指标：GV-13（阻断率、每千行诊断、error 级在成熟代码上的命中、延迟 p50/p95）。
- 判据：不劣化 + 绝对值如实报告。安全规则在成熟代码上命中少是正常的；
  稀有规则的精确率权重因此极高（6 次命中错 3 次 = 一半的阻断是噪声）。

### W9 评论级数据集的抽样框与位置重合计数（联网，**暂缓，只报告**）

- **目标**：只回答一个问题——**这份评论级数据集能不能当 L2 的抽样框**。它**不**产出精确率 / 召回率：
  「判据对象不同构」这一点已由 §4.7.3 判定，W9 只负责把那个判定变成一次可重放的测量。
- 数据集：`aacr-bench`（`eval-datasets.yaml`，`tier: B`）；**最小可行子集**（§4.7.4 实测）=
  `browser-use/browser-use` 的 3 个 PR / 16 条 note（label=1 6、label=0 10）/ 8 个 (PR, 文件) 对。
- 方法：按 `pr_target_commit` 从 `raw.githubusercontent.com` 取文件（**不 clone**，见 §4.7.4 的本机约束），
  用 `gh api .../compare/...` 取 PR diff 定 hunk 基准；把文件放进桩工作区，走**同一条判定入口**
  （§4.5 的运行前提：`validators.pipeline.run_pipeline` / `python -m policy.check`；上下文由 harness 显式声明，
  照 `thresholds.yaml` 的 `context.corpus` 口径），输出 **GV-16** 的 (c1, c0, n) 三个原始计数。
- 判据：**GV-16 无门槛**；禁止换算成精确率 / 召回率 / 一致率（§3 的口径纪律）；报告必须带 `reading_context`
  （哪棵树 = 哪个 `pr_target_commit`、哪个环境、哪套声明）。
- 成本：**≈ 2.4 MiB / 秒级**（实测，§4.7.4）；不做全量克隆。**止损线**：建立连接需要 > 1 人日，或下载 > 100 MiB，即停止。
- 证伪条件：① 最小子集上位置连接率 < 100% → 「抽样框」不成立，W9 关闭；
  ② 任何人给出**不由我们声明**的连接键（§4.7.3 的证伪条件）→ §4.7.3 的「不能当 L2」被推翻，W9 可升级为 L2 评测；
  ③ 若 W9 的读数被用来支持任何价值结论 → 该结论作废（R1）。
- 落点【提案】：`tools/governance_eval.py --suite relevance`（**实施前**必须先登记 `tools/README.md`；
  另注意 `evaluation/thresholds.yaml` 是严格模型、未知键会报错——加门槛就必须同批改它并递增它自己的
  `schema_id` / `version`）。这两处**不在**本次写域内，作为交接项留下。

## 6 实验设计与纪律

1. **独立 oracle**：标签来自第三方；同一 checker 另用第二个工具交叉验证（如 Semgrep / Bandit 独立跑一遍）。
2. **抽样与区间**：比例指标给 Wilson 置信区间；先按目标精度算样本量（例如要把 error 级精确率的区间半宽压到 0.05，
   需要多少条标注）。样本不够就写“样本不足”，不写“表现良好”。
3. **预注册与重记基线**：门槛先写进 `evaluation/thresholds.yaml`；行为有意变化时用显式 `--record` 重记并递增评测集版本，
   旧基线留在同目录作历史（与 `tests/fixtures/retrieval_eval/` 同型）。
4. **变异自证**：每个新仪器都要有一次“修复前会红”的证明，写进报告，不留“跑了、是绿的”。
5. **读数归属**：每个读数带 `reading_context`（哪棵树 / 哪个环境 / 哪套声明）与平台 revision；跨 revision 的数字不许直接比较。
6. **只报告 → 升格**：新评测步骤先进 `ci_local.py` 的 `REPORT_ONLY_STEPS`（非零退出只打印、不计失败，带 `expires_at` 复审日），
   **达到判据且至少有一次真实读数之后**再谈升格。绝不允许“先接成阻断再补数据”。
7. **成本可复现**：离线套件（W1/W2/W5/W8）必须能在无网环境跑完；联网套件记录下载量与耗时。
8. **带键的输出文件必须有版本轴**：`evaluation/thresholds.yaml`、`evaluation/corpora/*.lock.json`、
   `evaluation/results/*.json` 都是**有消费方**的载荷——加键或改语义必须按 **AGENTS 第 55 条**递增该载荷
   **自己的**版本号，并把它**登记进那张版本轴表**（表里没有的载荷，不等于可以不加版本号）。
   `tools/governance_eval.py` 的读数同理：`results/*.json` 必须自带 `schema_version` 与
   `reading_context`（哪棵树 / 哪个环境 / 哪套声明），否则第二个人重放不出来，也判断不了两个数字能不能比。
9. **接进本机门禁只能先进 REPORT_ONLY_STEPS**：这套 harness 若要进 `tools/ci_local.py`，只能先作为
   **只报告步骤**（非零退出只打印命中数、不计入门禁失败）并带 `expires_at` 复审日；
   升格（接成阻断）的判据必须先写下来（跑过 N≥1 次、0 命中、且 0 命中来自至少一次真实读数），
   **绝不允许「先接成阻断再补数据」**——与 `tools/obligations_gate.py` 的 L5 试用期同型。

## 8 分期与“如果只做一件事”

- **P0（离线，1–2 天）**：W1 + W2 + W8 的复现化 → 直接补上“精确率 / 误报率”这一格空白，
  并给第 10.4 节的标定建议一个可验证的做法。
- **P1（离线 + 外部语料，3–5 天）**：W5 故障矩阵固化 + W6 外部检索语料。
- **P2（联网，1–2 周）**：W4 Agent 端到端（要写事件渲染器与三态计数）。
- **P3（成本最高）**：W7 A/B。

- **暂缓（不进 P0–P3）**：**W9**（§5）。前置条件 = `eval-datasets.yaml` 的 `aacr-bench` 条目 `admission_todo` 清空
  （许可原文 + 「用 HF 快照还是上游当前版」的裁定）；在此之前它**只报告、无门槛**，而且它**不**回答「规则准不准」——
  那个问题仍然只有 W1（L1）、W3/W7（外部事实）与 GV-15（小样本人评）能回答。

**只做一件事就做 P0 的 W1**：它离线、秒级、可复现，而且答案很可能不好看——
而“敢把不好看的读数放进仓库”，正是这个仓库已经建立起的那条纪律。

## 9 这份方案不能证明什么（反面清单）

- 不能证明“规则之外没有缺陷”：规则没写的，平台不知道（对比报告第 1.8 节）；
- 不能外推到 Python 之外：43/43 条规则 `language: python`，非 Python 目标只有失败关闭或“按设计不取证”两条路；
- L1 全绿只说明“实现与工具口径一致”，不说明这些诊断值得报（Johnson 等 ICSE 2013 的现场研究把误报与“不可行动”列为采纳的主要障碍）；
- AgentDojo / InjecAgent 的工具面与 dsh 工具表不同构，“拒绝”里很大一部分会是 `capability_unavailable`：
  这是**设计正确**，但不能读成“规则拦住了”；
- CUAD / LexGLUE 只证明“文档 → 条款 → 规则”这条管线在别的规范语料上也能跑通，不证明工程规范的转化率；
- **43 条按支持面只有三档（本次实测，见 §4.5.2 的逐规则表）**：
  **有行级第三方标注（可比 P/R）26 条**（S 11 + E 10 + N 4 + TRY 1）、
  **只有文件 / 定义级标注 3 条**（DOC-002/003/004）、
  **无任何外部标注 14 条**（F 2 + I 1 + LOG 1 + 非 style_lint 4 + S 侧 N=0 的 6 条）。
  任何「43 条全部通过外部评测」都是错的；而且**每条结论都必须带它自己那条规则的样本量 N**：
  N=1 的 TRY400、N=2 的 N802/N803、N=5 的 N801 只能当冒烟，不许算比率；
- **片段物化通道（§4.5.3）只把 F 侧抬进分母**：F401 / F403 / F405 从「无外部标签」变成**文件级**
  （48 个正例文件 / 457 个负例文件，line 一律 0）；I001 与 LOG015 的候选接受率 39.0% / 20.2%
  **低于 50% 止损线**，按纪律**不写成「已覆盖」**——残留的 11 / 3 条正例只报告、不进主结论；
- **评论级数据集不能被告成检出级标签**（§4.7 已判定）：AACR-Bench 的 2145 条标的是「这条评论对不对」，
  与「这条规则在这一点命中」不同构；它不得进 GV-01 / GV-02 分母，也不得作 L2 的 TP/FP/FN 来源
  （直接当标签 = 跨层顶替 R2；自造映射再算一致率 = 自证 R1）；
- **错位不是漏报**：那份数据集没有任何「此处无缺陷」的采样，且论文自认真值不可能完备（核验文档 §3、OCR 文档 §7.2）；
- **HF 快照 ≠ 上游当前版**：恰好 1 条记录两侧标签相反（核验文档 §6.2 缺陷 A），不先裁定就不能引用；
- **OCR 文档的 R1–R10 与本方案的 R1/R2/R3 同名不同义**：引用时必须写 `OCR-R1…OCR-R10`（§4.7 开头）；
- 本文门槛全部是【提案】且未标定；任何引用必须带版本与 revision。
