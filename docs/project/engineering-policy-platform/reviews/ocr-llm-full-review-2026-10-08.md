### `.github/dependabot.yml:5` | high | bug | L34

Dependabot's pip updater only edits standard manifests (`requirements.in` / `pyproject.toml` here), but the artifact that actually determines installed versions is `requirements.lock` — a custom filename with a custom header, hash-pinned and generated by `tools/lock_requirements.py` (CI does `uv pip install -r requirements.lock`). Consider adding a workflow that regenerates `requirements.lock` on Dependabot PRs (pip `--dry-run --report` + `tools/lock_requirements.py`), or migrating the lock to a filename/format Dependabot recognizes and can update (e.g. the pip-compile `requirements.txt` convention with its standard autogenerated header).

```diff
        left += (0,) * (width - len(left))
        right += (0,) * (width - len(right))
        return (left > right) - (left < right)

    if operator == ">=":
        return compare(current, bound) >= 0
    if operator == "<=":
        return compare(current, bound) <= 0
    if operator == ">":
        return compare(current, bound) > 0
    if operator == "<":
        return compare(current, bound) < 0
    if operator == "==":
        return compare(current, bound) == 0
    if operator == "!=":
        return compare(current, bound) != 0
```
