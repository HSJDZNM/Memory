## 0. 一句话

判定内核是健康的：34 条历史问题（N16–N28 / M1–M5 / P1–P8 / Q1–Q8）里 **0 条**的根因落在引擎上；
30 臂确定性矩阵 **248 条检查跨轮 0 偏差**，且被第二方用自己的运算符表逐条重算过；
11 个 dsh 事件 fixture 在修前树/修后树**逐字段全等**。缺口的 **32/34** 长在**接缝**上，母体可以写成一句话：

> **平台把「它自己」——自己的配置、自己的失败、自己的状态、自己的覆盖——当成内部实现细节，
> 而它要求被治理者把这些东西当成一等数据。**

所以重构不是「再加一层」，而是**把平台自己纳入它已经强加给别人的三条纪律**：事实进数据、失败关闭、可证伪。
落地形态是**五件东西 + 六个台阶**；每一步都可独立验收、可回退，且不许踩 §5 的红线。

## 2. 母体：平台没有把自己当成治理对象

| 被治理者必须遵守 | 平台对自己 |
| --- | --- |
| 事实进数据（规则、注册表、语料都是 YAML） | 控制面的事实散在 YAML / hooks.json / profile patch / 环境变量 / 脚本常量 / 两门语言里，各有各的解析 |
| 失败关闭（未知一律拒绝） | 失败原因只有文本，且归因可以错（Q6）；自检缺席即通过（`check_wiring` 在无配置时返回空串） |
| 可证伪（每条能力都要有会失败的检查） | 覆盖、接线、版本漂移、仪器自身，大量性质**没有任何检查承载**（Q5/Q8/N13/N19/N20） |
| 状态要显式（跳过 ≠ 通过） | 状态被折叠：同一名字两种意思、不同东西同一形态、缺键与 null 同形 |

这解释了为什么每一轮「开新面」都会再冒出 5 条左右：新面暴露的都是**尚未被纳入治理的自我描述**。

## 3. 目标形态：五件东西（不是五个模块）

### 3.1 一套针脚（四个名字，一份实现）

| 名字 | 含义 |
| --- | --- |
| `evidence_tree_digest` | 取证时那棵影子树（AGENTS 第 48 条已有） |
| `referenced_files_digest` | 本次判据**读过**的文件集合（判据级封条） |
| `workspace_tree_digest` | 整个工作树（轮次级封条） |
| `platform_revision` | 产出这条判定的**平台代码**（范围由声明给出，不写死目录） |

- **一套函数实现**，落 `src/policy/worktree.py`（纯标准库、不 import adapters；adapters/validators 只读导入）。**该文件今天不存在**（独立验收已核实），所以本节是提案。
- **两层封条都要**：判据级回答「结论有没有被我读过之外的东西污染」；轮次级回答「这一轮有没有未声明的写者」。pre/post 各一次；不一致 → `invalidated`（不是 pass、不是 fail，门禁算红）。
- `platform_revision` 的范围**由声明给出**：本轮实测反例——树外写者改的 `policy-hook.plugin.mjs`、`tools/ci_local.py` 都在「src/policy + src/validators」之外，写死范围会让漂移判绿。

### 3.2 一张检查登记表（facts + checks 合表）

落 `validation/control-plane.yaml`：
- **facts 段（9 字段）**：key / authority(canonical|observed) / canonical_ref / consumers / predicate / severity / remedy / on_unprovable / expires。**不放值**（限制只作用于本段，否则会拒掉 checks 段）。
- **checks 段（8 字段）**：check_id / owner / command / covers / evidence_level / mutation_id / gap_note / severity。**只放指针**：出现 `last_run` / `status` / `passed` / `observed_*` 即加载期报错。
- **连接键** `facts.key ↔ checks.covers` **双向必查**；任一边悬空即红。给不出这条就拆回两张表。

合并的理由：**四个方案各自新增一个 YAML 就是母体的复发**。第二真源的反例：一次变异没跑成（`patch_not_applicable`）时表的形状一个字节不变，读者会把「checks 完备」读成「已证明」。

### 3.3 一个状态代数（两维，取代 N 个扁平状态）

格 = `(rule_id@version, checker, target)`，在一次判定、一棵树、**一个平台修订**上取值：
`verdict ∈ {passed, violated, not_evaluated}`；`reason` 只对 `not_evaluated` 有值，且是受控集合：
`out_of_scope` / `missing_dimension` / `no_subject` / `no_provider` / `not_covered_by_design` / `blocked(kind)` / `pending_precondition`；**未知 reason 一律 block**。

三条合并规则：blocker 与 pending **只撤判定不撤证据**；覆盖范围不许超过它真正服务的那一半；「被划掉」与「没参与」必须能分开读。

**一次性义务的键**（独立验收确认的设计缺陷修正）：不能用 `tree_digest` 作键——每次写盘都换树，键必变，拼错的 import 会永久停在「待实现」。
改为 `(session_id, rule_id, target, normalized(missing_targets))`，**按方向判一次性**：`missing_targets` 严格缩小 → 放行；持平或扩大 → block（`pending_not_renewable`）。

### 3.4 一个归因闭集（+ 核验前置）

`origin` 是闭集（`platform.*` / `agent_runtime.*` / `host.*` / `project.*` / `unknown_origin`），每个 origin **必须**携带：
`owner` / `object{kind,value,source}` / `observation{method,result,verified,verified_at,run_scoped}` / `fix` / `causal_link(proven|unproven)`。**写不出 `fix` 的 origin 不许存在**。

**核验前置**：每条指控在写进理由之前先执行它的证伪判据（报「可执行文件不存在」先 `stat` 它；报「工作目录不存在」先 `stat` 并判目录）。核验允许证伪自己人——判据不成立时只能落到 `unknown_origin`，不许换一个对象继续指控。
三处伪造面必须同时处置：核验对象必须是模型**写不到**的东西；记 `verified_at` 与 `owner_note` 防时间差；核验记录**无权威**，消费者不得据它 allow/block。

### 3.5 一份边界裁定 + 三数分离的报告

- **边界裁定**：把「平台治理受控会话、不治理使用者日常入口」这条**已经做出但只写在 CI 注释里**的决定（`.github/workflows/phase-8.yml:266-272`）提升为顶层契约。
- **载体** `adapters/wiring-scope.yaml`：每条通道给 `decision(in_scope|out_of_scope|expected_absent)` + `kind` + `owner` + `reason` + `consequence` + `expires_at` + `renewals`。
- **报告只报三数**（`discovered` / `declared` / `measured`）与**五个差集**：`discovered_not_declared`、`declared_not_discovered`、`in_scope_not_wired`、`out_of_scope_active`、`out_of_scope_expired`。
- **不许出现比例**：顶层只允许 `account` / `differences` / `channels` / `reading_context` / `headline`；计数一律整数、禁浮点、禁 `ratio`/`percent`/`coverage` 键名，键集合随 `wiring_schema_version` 冻结。

## 4. 六个台阶（每步：内容 / 红→绿 / 回退 / 分歧状态）

### 台阶 0 · 先决条件（零判定影响，纯新增读数）

**回退**：删 `worktree.py` 与两处调用。**分歧**：已消解（四方都接受两层封条；反方接受「发现集不可冻结、分母由声明拥有」）。

### 台阶 1 · 归因最小收口（只改理由，不改判定）
**内容**：`origin` 闭集 + 核验前置，先覆盖两族最高频：spawn 输入族（JS 侧）与配置族（Python 侧）；跨语言契约用例（**真实插件产出 → 真分类器**，不许只喂手抄字面量）。
**红→绿**：**R-g**——工作目录**存在**而 spawn 抛 ENOENT 时，理由不得说「工作目录不存在」，必须说「问题不在目录这一侧」。
**回退**：删 `origin` 字段与核验两步。**分歧**：与树外写者同向（它已落地 AGENTS 第 52/53 条并加了跨侧用例）；但**本轮不为它背书**（见 §9）。

### 台阶 2 · 状态镜像与「没跑 ≠ served」
**内容**：H4（写测试文件时 pytest 记 `ok`、`served_checkers` 仍含 `failing_tests`，而**零个测试被执行**）、H5（选择期证据被丢弃）、H1（`block` 与 `violations=[]` 的组合被消费方读成「没有依据」）。
**红→绿**：**R-f**——`served_checkers` 里的每个 checker 必须有**真实执行**的证据：必须有验证器记录 `status ∈ {ok, findings}` **且**（`evidence_count > 0` 或该次运行确实没有该 checker 的对象，并由**验证器**给出对象判定）。**不允许检查自己用「显式 no_subject」改名修绿**。今天必红（R0/R1 逐字节相同）。
**回退**：按 L1 只递增 `AUDIT_SCHEMA_VERSION` 1.0→1.1。**分歧**：与树外写者对立（AGENTS 第 51 条把 `pending` 定成 **warning 级 violation**，违背第 46 条对 `violations` 的定义）。

### 台阶 3 · pending 的决策表达与义务账
**内容**：`pending_precondition` 进决策表达（**不记 warning violation**）+ 义务账（键与方向判一次性，见 §3.3）+ 判罚点 = 本机门禁（真树真工具；清点只报计数与年龄，不判罚）。
**红→绿（已按独立验收 D7 解耦）**：**J1 结构判据**——在受治理会话里按「先写测试、再写实现」的顺序推进时，判定记录必须同时满足：(a) 出现 `pending_precondition` 且带义务；(b) `violations` 里**没有** pending 条目；(c) `obligations_open > 0` 时 `check_volume.complete = false`；(d) 解除只由**一次真实 pytest 运行**判定。
**为什么必须解耦**：树外写者已把「不再产生 critical」这一半落地，原判据「不再被拦」**不做事也会绿**。
**红→绿（R-d 合规）**：本步改变决策表达，**必须先给出字段级 decision 差集**（受影响 fixture 清单 + 逐字段差 + 快照重记），否则不许合并。
**回退**：义务账只进审计，删字段即回退。**分歧**：与树外写者对立（warning vs `not_evaluated`），且对方已写进 AGENTS 第 51 条——**采纳本步等同修订该条，必须同批提交**（见 §10 第 1 条）。

### 台阶 4 · 覆盖账与仪器自证
**内容**：`governs` 轴（按 `kind` 分档 + 「有意治理另一棵树」的声明位）+ `reading_context` + 声明差集 + **退出码语义** + 豁免到期与续期 + 会话窗口 + 仪器自证 + 写权租约。
**红→绿**：
- **R-h**（仪器自证闸）：门禁步骤名无 `check_id`、或 `mutation_id` 为空且 `gap_note` 为空、或变异返回 `patch_not_applicable`——三种输入都退 1。
- **`in_scope_not_wired` 必须是一条红条件**（不是自述）：同一棵树上，**已声明在范围内却没接线** → 退 1；**已声明 `out_of_scope`** 的对照臂 → 退 0 且出现在 `out_of_scope_active` 里；**没有声明**的通道 → 退 1（`discovered_not_declared`）。
- **退出码补格**（独立验收指出缺的一格）：环境声明「没有运行时」（`expect_runtime: false`）却发现了通道 → **退 1**。
- **反退化**（独立验收 D-J4）：候选根全部不可达而三数全 0 → **退 1**（它与 `expect_runtime: true` 的声明矛盾），不许退 0。
**参数纪律（L9 单调收紧）**：命令行参数只许更严不许更松；`--environment` 只**选择声明段**，不改变判定；`--require-runtime` 这类收紧开关允许把 `skipped` 变红。
**回退**：逐步回退（各步独立）。**分歧**：L6-4 的字面要求已按 D 的反例修正为上面的形态。

### 台阶 5 · 控制面事实表与跨源互证
**内容**：A 的步 1（只报告）→ 步 2（合并谓词：一份实现、两个调用点）→ 步 3（跨源互证，走 **L5 上线闸**）。
**红→绿**：预算不等式两套结论（运行期报错 vs 静态 `wired`）、测试路径两份声明（实测 **101 个文件**不一致）、工具表/检查器三处声明。
**L5 上线闸**：任何新的加载期 FATAL（拒绝启动）**必须先以 `warn` + 非零退出跑满一个轮次**，收集真实实例；升格判据 = 「跑过 N≥1 次且 0 命中」，**0 命中必须来自至少一次真实读数**；warn 期读数同时给出仓库内与 `.tmp` 实例并带树摘要。
**回退**：步 3 单独提交、单独回退（它是**唯一**会让「配置写错就起不来」的一步）。**分歧**：B 指出 `src/adapters/dsh/adapter.py:978-982` 是既有「直接 FATAL、无 warn 期」的先例，必须补登记为例外。

### 5.3 封条三段式（所有判据统一跑法）
`seal(pre) → 跑判据 → seal(post)`；`pre != post` → 退出码 2 + 输出 `{added, modified, removed}`，**本次全部判据结论作废**。
状态只有四个：`pass@<tree_digest>` / `fail@<tree_digest>` / `external_write` / `unprovable`（依赖读不到**不是** pass）。

## 6. 最小可行子集（L7′）

**四条**：
1. 轮次封条 + 修订针脚（§3.1）；
2. **拆成两步**：②a 归因最小收口（台阶 1）；②b 状态镜像 H4/H5（台阶 2）——不能合成一步（实测证明 pending 落地**没有**碰 H4）；
3. 边界裁定 + **范围声明的数据文件** + 三数分离（没有数据文件则「声明 M」没有载体，J4 不可能绿）；
4. **最小自证载体**（checks 段 + 「既无 `mutation_id` 又无 `gap_note` → 红」的守门）——没有它 J5 不可能绿，L5 的上线闸也失去载体。

**只做前三条的诚实代价**：**J4 与 J5 保持红**，不许声称绿；**R-b 也仍然红**（pending 记 warning 的残余只有台阶 3 能修，而台阶 3 不在最小集里）。
