### 1.2 租户与项目边界（【实测】，§9.1）

- 令牌被授权多个租户却**不写** tenant → 403 `token_scope_mismatch`（"不得由服务端替你选一个"，`src/policy_api/auth.py:174-178`）；写越权租户 → **401 `unauthenticated`**（刻意与"不存在"同码，:167-170）；写对 → 200。
- 项目边界 = 租户声明 ∩ 令牌声明（`src/policy_api/auth.py:110-126`），越界 → 403 `project_not_allowed`（:184-186）。
- 配置里的 `rules_root`／`project_root`／`validation_root`／`audit_log` 是**部署数据**，不是界面可编辑项（`api/policy-api.yaml:47-78`）。

### 3.3 "没有任何跳过门禁的路径"的三条论证

1. **结构上无写路径**：6 条路由没有一条能改文件（`runtime.py:73`）；写只能经 `orc.policy.edit`，其 approval: required 是**数据**（`tool-registry.yaml`:317-345），pre-check 顺序固定为
   registry → action_window → principal → permissions → approval → policy → rate_limit → circuit_breaker → ledger → audit（`src/enforcement/precheck.py:5-8`），任一项 FAILED 即 block（:82-86）。
2. **状态前进只能由后端结论驱动**：D2/D3/D4 每次前进都必须携带某条命令或路由的返回（退出码 0／200 + 载荷），界面不产生结论（可行性评估.md:101 的 R1）。
3. **"部分生效"在数据结构上不可表达**：C23 一条坏=整批不加载；空规则集**拒绝**替换正在服务的规则集（`services.py:88-94`）。所以只有两种终局：整批生效，或"现网规则集未被替换"。

### 3.4 severity: warning 只告警（DOC-001 的例子）

决策表：无 violation → allow；info／warning → `allow_with_warnings`；error／critical → block（`src/policy/models.py:172-174`、:969-987）。
【实测】对一个缺 docstring 的文件跑 validate：decision=`allow_with_warnings`、violations=2（DOC-001，severity=warning），证据带 `py.docstring@1.0` 与修复建议。
界面要求：warning 用**琥珀色**并写明"告警不阻断"，不与 block 共用红色，也不写成"通过"。

### 3.5 `skipped_rules` 与 allow 的区别

| 情形 | 后端事实 | 界面文案 |
| --- | --- | --- |
| 通过 | allow 且 matched>0 且 skipped 已解释且证据流水线跑过 | "本批规则判定通过" |
| 无规则管辖 | allow、matched=0 | "没有任何规则覆盖这次上下文"（不是通过） |
| 规则被跳过 | decision.`skipped_rules`[].reasons，如 language <missing> != python；证据类 checker 另有"需要验证器证据" | 逐条列出跳过规则与原因 |

【实测】同一请求：context 缺 language → allow、matched=0、skipped=6；补上 language=python → matched=1、skipped=5。
两种都是 allow，含义完全不同。这正是 `README.md:56`-57 与文档 §1 想说的那件事。

### 4.2 错误码覆盖情况

- 受控枚举 33 个错误码，状态码由 `STATUS_BY_CODE` 推导（`src/policy_api/errors.py:29-107`），契约测试断言枚举与映射一一对应（`tests/unit/test_api_contract.py:97-119`）。但**响应形状没有快照守护**：`skipped_rules` 在 `api/openapi.json` 里 0 处命中（grep），因为路由不声明 `response_model`（`src/policy_api/app.py:270-273`）——它的守护者是 `tests/integration/test_api_http.py`，**不是** `openapi --check`。界面依赖的字段必须另有契约测试兜底。
- 界面必须按 code（而非 HTTP 状态）分支：401 同时覆盖"令牌不认识""租户不存在""越权租户"（`errors.py:7-9`；`auth.py:167-170`）。
- **声明了但服务端路由不会产出**的码（全仓 grep 无抛出点）：`evidence_unavailable`、`query_invalid`、`target_invalid`（只有枚举声明，真实抛出点在 Phase 6 Runtime `src/adapters/runtime.py:871-919` 与编排侧）、`policy_unavailable`（仅作为**客户端侧**探针桥接的合成字符串出现，`src/policy_api/probe.py:152`、`:162`）、`idempotency_key_missing`（**从未使用**：缺键是合法的，`runtime.py:899-902` 直接返回 `None`）。它们**不能删**——`contract.py:133-139` 对枚举与映射做全等比较；准确定位是「**跨层公共词汇**」，不是「预留」。界面不要为它们写专门分支，但**必须**保留"未知错误码原样显示"的兜底分支。
- 一处措辞不一致，需以后端为准：`api/README.md:99` 写"租户不存在、越权租户对外同样是 401"，而 `auth.py:182` 在"租户未声明／被禁用"时抛 TENANT_NOT_FOUND（404）；`errors.py:7-9` 的注释又写"跨租户／不存在永远是 404"。三种说法只能有一种进界面文案。

### 4.3 三条渲染不变量（可写成断言）

- G1：**绿色只属于 allow 且 matched>0 且 skipped 已逐条解释**；其余一律中性或红色。
- G2：**未知 ≠ 通过**：超时、503、504、429、未识别错误码、网络失败一律渲染为"没有结论"，且禁用任何"继续"入口。
- G3：**每条状态文案必须能指回一个后端字段或错误码**（§4.1 右列即验收依据）；指不回去的文案不许上线。

## 8. 前端技术形态建议

| 形态 | 长什么样 | 代价 | 与本仓库的契合度 |

| C 桌面壳或 CLI 包装 | 本地进程直接读写文件，绕开 HTTP | **与红线冲突**：等于给控制台第二条写入路径 | 低：除非只做纯只读查看 |
| D 反向代理同源（静态由别的进程提供，`/v1/*` 反代） | 浏览器只看到一个源；API 代码零改动 | 多一个部署件与代理配置 | 高：不把前端塞进判定进程，也不影响契约 |

**CORS 是硬约束，不是偏好**：应用没有注册任何 CORS 中间件（`src/policy_api/app.py:172-182` 全文无 `add_middleware`；`src/` 下 `CORSMiddleware`／`StaticFiles` 命中 0 处，grep 复核），独立源前端（如 Vite 5173）连 200 响应都读不到——对方实测预检 `OPTIONS` 返回 405 且无 `Access-Control-Allow-Origin`。选 B 必须先加 CORS 中间件。

**同源有两条零代码改动的路，A 是其中最省依赖的一条**：

- **A（同源静态挂载）**：`app.mount` 把静态目录挂进同一进程。**它不改变 OpenAPI 契约、不需要 `openapi --write`**——我复核了 `contract.self_check`：`openapi_paths` 比的是 OpenAPI 文档里的 `paths`（`src/policy_api/contract.py:144-151`），`Mount` 不进 `paths`；契约测试按 `route.name` 过滤已登记端点（`tests/contract/test_api_protocol.py:174-178`）。代价是前端与判定传输层同进程。
- **D（反向代理同源，对方 D① 建议）**：静态文件由另一个进程（或既有 Web 服务器）提供，`/v1/*` 反代到 Policy API。浏览器看到的仍是同源，**零代码改动、零契约影响**，且不把前端塞进判定进程。代价是多一个部署件与一层代理配置。

只有**新增走 `runtime.handle` 的 API 路由**（G1–G6 那些）才需要改契约三件套：`ROUTES`／`contract.ENDPOINTS`／`api/openapi.json`，并按 `AGENTS.md:225-228`（第 31 条）跑 `python -m policy_api.cli openapi --write`（`--check` 是 CI 门禁，流程见 `api/README.md:124-131`）。
推荐 A，并沿用分期：P0 只读与预演；P1 草稿与结构化编写；P2 审批与提交；P3 溯源与漂移治理（可行性评估.md:116-121）。
若引入 Node 工具链，按 `AGENTS.md:307` 一次补齐：依赖清单与锁文件、README 的安装／构建／测试／运行命令（必须可执行）、CI 配置、.gitignore 条目。
P0 之前"前后端能不能连"更适合先用 curl／探针证明，避免把不稳定契约固化成界面。
