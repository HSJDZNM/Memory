## 2. Lead 裁决 D1–D15

每条格式：**议题 → 各方主张 → 裁决 → 依据 → 对终稿的约束**。

### D1 板块切分线：不是目录、不是 Phase，而是「谁能产生结论」

- **主张**：kernel-analyst 提出按「能否产出 allow/block」切 9 个板块（S1–S9），并否决了 5 个替代方案（按六层、按 Agent、按 Phase、按 CLI 入口、把检索与语料拆开）。Red-team 追问：第 9 块（操作台）今天连路由都没有，凭什么算板块？
- **裁决**：**采纳 S1–S9**；S9 保留但**降级为「只读视图 + 申请单」，并显式标注提案态**。切分线只有一条：**只有 S1 产出 allow / allow_with_warnings / block**，其余八块各自翻译、执行、产证据、取语料、传协议、排下一步、复跑门禁、显示。
- **依据**：AGENTS.md 约束 30 与「三条唯一」（`docs/project/architecture/功能清单.md:25-29`）；`policy.engine.evaluate` 是唯一判定路径。
- **约束**：01 的每个板块必须写「它**不行使**什么权力」；任何新增板块若自己产出结论，一律回到 D1 重裁。

### D2 规则集口径：工作树是事实，但要带「取数时刻」

- **主张**：kernel-analyst 先报 26 条，ui-architect 报 45 条，flow-analyst 报 44 条，red-team 复现不出 46。同一小时内三次翻车。
- **裁决**：① 口径 = **loader 读到的文件系统**（`src/policy/loader.py:196-228`），因此「工作树实况」是运行期事实；② 「受跟踪基线」（`git ls-files policies`）是另一列，**两者并列显示，差异本身是信号**；③ 任何计数、哈希、条目数必须以 **[值 + 取数时刻 + 取数命令] 三元组**出现，**禁止**把数字写成文档常量或在界面里烘死。
- **依据**：`AGENTS.md` 约束 2（规则是数据）、4（原子加载）、36（凭据变化即失效）；X9。
- **约束**：01/02/03 三份终稿里的每一个数字都必须带三元组或写成命令而非数值；`README.md` 的速览表同样适用。

### D3 阻塞项 B1 必须先修，且修法在**注册表数据侧**

- **主张**：三份 R1 都把 B1 写成「新建规则文件」的单点缺陷（改 `nodes.py` 的工具选择分支）。red-team 用真实注册表证明：`orc.fs.write` 无审批放行**任意路径**，包括受已审核哈希保护的信任根数据。反方最强论点（red-team 自述）：该路径有台账与审计，所以是「有账无门禁」，不是无声后门。
- **裁决**：**采纳 red-team**。① 修 Node 侧选择分支**只是必要条件、不是充分条件**，真正的修复落在注册表数据：给无审批写工具加**敏感路径拒绝**（`policies/`、`registry/`、`adapters/`、`api/`、`validation/`）或改为**正向白名单**；② 「有账无门禁」仍然是缺陷——OS 的承诺是「变更必须**被批准**」，台账记录的是「**发生过**」；③ 修完必须补契约测试（`Change(path='policies/x.yaml', content='y').tool_id == 'orc.policy.write'` 与 precheck 对敏感目标 exit 1）。
- **依据**：X1、X2、`AGENTS.md` 约束 13/14/16/39。
- **约束**：02 的 E 流程与 03 的治理写入页在 B1 修复前**只允许出现「不可用 + 原因 + 替代命令」，不得展示 `action_hash`、`post_checks`、审批人三个展示块**（ui-architect 在 R2 主动撤回了原设计）。

### D4 阻塞项 B2 必须先修，且「未核对」不等于「无漂移」——它要**阻断提交**

- **主张**：red-team 的 O1 问：B2 修好前，界面把漂移列写成「未核对」是止损，但「未核对」是否应当阻断提交？
- **裁决**：**阻断**。理由：允许在未知溯源状态下推进，等于让「不撒谎」在最后一步失效。三态模型固定为 **未核对 / 已核对且一致 / 已核对且漂移**；**只有「已核对且一致」允许进入提交节点**，「未核对」与「已核对且漂移」一律阻断。（R3 红队指出原句「前两态都不构成依据」在字面上会让提交路径永久不可达——此处以这句显式枚举为准，02 §1-C 与 03 I6 同步。）
- **依据**：X3、`AGENTS.md` 约束 12（漂移不许静默）。
- **约束**：03 §7 的失败语义表必须含「未核对」行；02 的 C 台阶 7 与 E 流程必须写出阻断点。

### D5 新增阻塞项 B3：幂等重放不得返回空壳

- **主张**：flow-analyst 在 R2 发现（两份 R1 都没有）：响应超过 8192 字节上限时，幂等重放返回 `200 + {}`，下游读不到 `decision` → `policy_unavailable` → `blocked`；`orchestration_loop` 与 `phase_evidence` 今天因此是红的。
- **裁决**：列为 **P-1 期的第三个阻塞项**。规则：幂等重放要么返回**完整决策载荷**（含 `decision` 与 `rule_set_hash`），要么返回**显式错误码**；**禁止** `200` + 空体这种「成功外表下的没有结论」。同时：判定调用**不得携带幂等键**（编排层的幂等键是它自己的，不该拿来复用平台响应缓存）。
- **依据**：X6、X7；`AGENTS.md` 约束 33（失败关闭没有例外）。
- **约束**：01 的 S6 接口面新增一行「空壳重放 = 没有结论」；03 必须为 `Idempotency-Replayed: true` + 空体画出「没有结论」态。

### D6 板块表新增「今天可达性」列

- **主张**：kernel-analyst 在 R2 自我推翻：他把 `evidence_unavailable`、`policy_unavailable` 列为可达 503，实测这两个码在 `policy_api` 里 0 抛出点。ui-architect 也发现 `capability_unavailable` 同类。
- **裁决**：**采纳**。可达性三值：**可用 / 存在但 0 抛出点 / 不存在**。界面**不得**为「存在但 0 抛出点」的码画分支或写文案，只可以在「契约表」里以灰色登记（并注明它是契约预留）。另：`GET /v1/openapi.json` 虽然在契约 paths 之外，但确实挂着且未认证，必须出现在路由表里并标「未认证 / 非契约」。
- **依据**：X5；verifier 的 F7 核验。

### D7 界面第二判定必须删除，不是「标注模拟」

- **主张**：red-team 的 A1 判定这不是风险而是**已发生的违反**（`app.js:198`）；flow-analyst 补充 `:365`「预演通过」连「浏览器内模拟」标注都没有。
- **裁决**：**删除前端判定函数**，并把预演改为**调用后端同一套代码**（`policy.loader` / `validators.registry` / `policy.checkers`）；在后端预演路由到位之前，整块功能标记【未实现】，**不得**以「模拟」名义保留计算。新增可断言项：前端不存在以 `severity` 为输入、以决策值为输出的函数；`designs/console/**` 扫描决策字面量的命中集合必须等于白名单。
- **依据**：X4、`AGENTS.md` 约束 30；`docs/project/engineering-policy-platform/designs/文档转规则操作平台-前端交互逻辑.md` 的反模式清单（自由文本判定、保存即生效）。

### D8 失败语义铁律（三份终稿共用一段，不许各自表述）

- **裁决**：
  1. **退出码 0 ≠ allow**（`outcome_code=context_error` 也会 exit 0，见 flow-analyst D6 实测）；
  2. **`skipped_rules` ≠ 通过**；跳过的规则必须显示**原因**，缺 `include_evidence` 时不得渲染「通过」；
  3. **超时 / 503 / 504 / 429 / 空壳重放 = 没有结论**，不是「稍后放行」；
  4. **提交节点的唯一判据**：`pre.checks[check == "approval"].status == "passed"`；`skipped`、`failed`、过期**都不等于通过**（flow-analyst 在 R2 按要求写出正例/skipped/失败三组实测输出）；
  5. **门禁绿只证明检查项通过**（D10）；「没有规则管它」不得渲染成「它合规」。
- **依据**：`AGENTS.md` 约束 33/37/38；`术语与口径.md:27`、`:170`；X7。

### D9 界面不扩权：不隐藏入口，只显示服务端原文

- **主张**：ui-architect 在 R2 撤回了自己的「按角色隐藏入口」列名——一边承认角色不可回读（N5），一边按角色裁剪，等于界面自己做了授权判断。
- **裁决**：**采纳撤回**。列名改为「**角色可服务性**」：不隐藏入口，**不做本地授权判断**，401 / 403 原样显示服务端返回（含错误码）；`metrics` 页对非运维角色显示服务端 403，不显示「无权限」以外的推断。所有 `evaluate` 请求显式带 `include_evidence=true`。
- **依据**：`AGENTS.md` 约束 32/33；N5（前端无身份）。

### D10 「当前全绿」这句话不许写进任何终稿

- **主张**：red-team 的 V21 声称「六个门禁全 exit 0」；ui-architect 指出门禁绿不证明规则集/索引未变；flow-analyst 实测今天 `orchestration_loop` 与 `phase_evidence` 是红的。
- **裁决**：**采纳三者**：① V21 加限定（绿只证明检查项通过）；② 终稿只允许写「**逐条命令 + 退出码 + 取数时刻**」，禁止「全部通过」这种总结性断言；③ 顶栏必须常驻显示 `rule_set_hash` / `index generation` / 取数时刻，且**允许显示红**。
- **依据**：X9、X7；`AGENTS.md` 工作方式 5（门禁前移）。

### D11 溯源按规则逐条显示，不许整页断言

- **主张**：两份 R1 写「溯源为空 / `rules --rule` exit 1」；red-team 实测 `DOC-001` 已 exit 0，只有 `ARCH-001`、`STYLE-013` 仍 exit 1（`AGENTS.md` 新增约束 40 已把溯源登记写成硬要求）。
- **裁决**：**采纳 red-team**。溯源是**逐规则**状态：`未登记 / 已登记且可解析 / 已登记但解析不到 chunk`，三种都必须能单独显示；整页概览只能给计数，不能给结论。
- **依据**：X8；`AGENTS.md` 约束 40。

### D12 操作系统隐喻：只用来解释，不用来推导

- **主张**：red-team 的 M1–M5 与 kernel-analyst 的 M1–M7 高度重叠：隐喻会诱导出「安装/卸载规则」「界面是第二内核」「有进程隔离」「有调度器」「`policies/` 是通用文件系统」。
- **裁决**：**只用于解释**。凡要写进接口、路由、字段、按钮的设计决定，依据必须回到 `file:line` 或 `AGENTS.md` 约束编号，**不得**回到「操作系统一般怎么做」。01 保留隐喻映射表，但**同等篇幅**保留「隐喻不成立」一节；`安装 / 卸载 / 调度器 / 沙箱 / 第二内核` 五个词在终稿中一律写成「隐喻，不成立」。

### D14 S9 操作台的定位：仪表盘 + 申请单，不是内核

- **裁决**：S9 **不是**第二个内核，也不是「控制面板」（控制面板暗示高于被控对象）。它只有三种动作：**看**（渲染服务端事实）、**发起**（生成申请单）、**指路**（给出等价 CLI 命令）。今天它连路由都没有（N1/N3），因此 P0 之前不得在任何页面出现**对操作台自身**的「可用 / 已上线」措辞（数据可达性表里的「可用 / 不可达」是取数字段的技术分类，不受此限）。

### D15 文档纪律：`file:line` 必须可复核，漂移即缺陷

- **裁决**：终稿的每个 `file:line` 都要能被复核（X10 已发现两处既有漂移：`models.py:267` 被写成 `:255`、`功能清单.md` 整体偏移约 70 行）。**本设计的文档不复制会漂移的行号结论**：凡是行号，必须同时给「可复核命令」；已知漂移登记为**既有缺陷**，与本设计解耦（不在本次修复范围）。

## 5. 给读者的最短结论

1. 这个仓库**已经**是一个操作系统：内核是判定、系统调用是 **6 条契约路由 + 1 条运行时 OpenAPI 端点**（未认证且不在契约内的 `/v1/openapi.json`）与 7 个 CLI、驱动是受控执行与验证器、文件系统是数据契约、进程与调度是编排、包与安装是已审核哈希、日志是摘要链。
2. 缺的不是内核，是**唯一一块没有结论却最容易长出结论**的那层：**操作台**。三处 P-1 阻塞项已修；下一步仍应先只读上线，最后才给「申请单」。
3. 全程不许出现第二份判定；不许把「没有结论」渲染成「通过」；不许把数字写成常量。
