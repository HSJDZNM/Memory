### 2.1 顶栏字段（D2：每个数字带取数时刻；D10：允许显示红）

| 字段 | 来源（今天） | 取数时刻 | 可用性 |
| --- | --- | --- | --- |
| 服务 / 部署 / 存活 | `GET /v1/health/live`（**免令牌**，实测 200） | 每次渲染 | 可用 |
| 就绪 | `GET /v1/health/ready` → `state` / `detail`（免令牌，实测 200 `ready`） | 每次渲染 | 可用 |
| 规则集哈希 + 计数 | `evaluate.rule_set`，或 `ready.tenants[].checks[rule_set]` | **必带** | 可用（分钟级变化） |
| 索引 generation | **无网络面**；`python -m retrieval.cli stats`（须标「CLI 快照」） | **必带** | CLI 快照 |
| 租户 / 项目 | **无 `/v1/session`**（N5）；`metrics.tenants` 是**全量装配租户**，不得当选择器 | — | 不可用 |
| 身份 / 角色 | 无路由可回读；只有令牌自身声明 | — | 不可用（标「令牌声明，未回读」） |
| 连接状态 | `live` + `ready` 的实际状态码；**允许红**（D10） | 每次渲染 | 可用 |

**顶栏纪律**：① 每个数字右侧灰字标注取数时刻，悬停给出取数命令；② 禁止把哈希写成构建期常量；
③ 若某值只能来自构建期快照，必须显式标「构建期快照」，不得与运行期取数混排。

### 2.2 侧栏 / 内容区 / 证据抽屉 / 状态条

- **侧栏**：只有 8 个页面入口，**没有任何操作按钮**，不携带状态色（避免「没红就是绿」）。
- **内容区**：页面标题行固定三段——页面名 / `S 板块：S<n>` / 「本页不行使的权力」一句；页脚逐条列出本页每个数字的取数命令与退出码。
- **证据抽屉**：装载字段三类，只读、无编辑控件（D7 / 约束 32）：决策载荷（`decision` / `matched_rules` / `skipped_rules[].reasons` / `violations`）；验证报告（`report.evidence` / `blockers` / `served_checkers` / `truncated_evidence`）；`request_id` / `trace_id`。
  **抽屉不得提供 `decision_ref` 手填框**——它只能由本会话的 `evaluate` 产生。
- **状态条**：逐条命令 + 退出码 + 取数时刻；未识别错误码计数；`<noscript>` 提示；**允许出现红色**。

## 3. 逐页设计

线框图例：`[灰]` = 今天没有对应路由的控件（可聚焦，读出缺口 + 替代命令 + 禁用原因）；`?` = 「为什么不能在前端补」。
「三态」= **空态**（还没有取数）/ **错态**（有明确错误码）/ **降级态**（依赖不可用、构建期快照、部分不可读）。
「角色可服务性」= 是否隐藏入口、以及服务端会回什么（**不做本地授权判断**，D9）。

### P1 总览（首屏 · 跨层）

```text
+---------------------------------------------------------------------------+
| 连接  live 200 / ready 200 ready @20:56:08                                 |
| 规则集 sha256:a90e64ac… 44 条 @20:56:08 (python -m policy.check --check-rules) |
| 受跟踪基线 6 份（git ls-files policies @20:56）  ← 差异本身是信号             |
| 索引 generation 4 · 1013 chunk @20:56      (CLI 快照, 无网络面)              |
| 语料 datasets=6 entries=42 @20:56    (python -m retrieval.cli verify)        |
| P-1 修复：B1 / B2 / B3 —— 逐条给「已修复 + 回归证据」                          |
+---------------------------------------------------------------------------+
| 入口：[判定工作台] [能力层] [数据与契约] [证据与门禁] [边界与路由]            |
```

- **元素与来源**：连接卡 = `health/live` + `health/ready`（【实测】）；规则集卡 = `check-rules`（【实测】@20:56:08 → `44` / `sha256:a90e64ac…`）+ `git ls-files policies`（6 份）；索引卡 = `retrieval.cli stats`（【实测】`documents=42 chunks=1013 generation=4`）；语料卡 = `retrieval.cli verify`（【实测】`entries=42` exit 0）。
- **三态**：空态 = 未取数（显示「—」与「尚未取数」）；错态 = 任一响应的状态码与错误码原文；降级态 = `state=degraded` 时**逐租户**展开 `checks[]`，禁止合并成一句「服务正常」。
- **角色可服务性**：不隐藏任何入口。developer / ops 看到同一份只读卡；`metrics` 卡对 developer 显示服务端 403 `metrics_forbidden` 原文。
- **禁止**：不渲染「1 个待审批动作」这类 KPI（N4 无审批中心）；不渲染「总体健康」总分。

### P2 判定工作台（③ 判定核心 · S1）

```text
+-------------------------------------------------------------------------------+
| 文件[src/policy/engine.py] 层[capability v] 语言[python v] 操作[edit v] [运行判定] |
| ? 层取值只来自 src/policy/check.py:77-92 的 12 个值 + unknown（当场复核）        |
+-------------------+-----------------------------------------------------------+
| 结论 allow        | matched / skipped / violations 与响应大小均来自本次 API 载荷；超过幂等上限时显示结构化错误 |
| 中性灰：没有规则覆盖这次上下文（不是通过）                        [证据抽屉 ->] |
+-------------------+-----------------------------------------------------------+
| skipped_rules（逐条带 reasons；本页请求恒定 include_evidence=true）              |
|  DOC-001@1  checker missing_docstring 需要验证器证据；本次调用只提供上下文…      |
+-------------------------------------------------------------------------------+
| [灰]保存为用例  原因：幂等台账无读路由  替代：无（今天只能靠 request_id 反查日志） |
```

- **元素与来源**：表单枚举 = `KNOWN_LAYERS`（【读码】`src/policy/check.py:77-92`，12 值 + `unknown`）+ 五值 `operation`；结果面板 = `evaluate` 响应（`decision` / `matched_rules` / `skipped_rules` / `rule_set_hash`）；`operation` 的取值来自 `src/policy/models.py` 的操作枚举（复核命令：`Select-String -Path src/policy/models.py -Pattern 'class Operation' -Context 0,8`）。
- **三态**：空态 = 「本页还没有任何结论」；错态 = 400 `context_invalid`/`body_invalid` 或 401/403，**原文错误码**直显；降级态 = 504/503/429 → 「没有结论」（§7），**不显示任何结论色**。
- **角色可服务性**：不隐藏；developer 与 ops 对同一请求必须看到同一份载荷（约束 30：本地与经 API 的决定整份相等）。
- **禁止**：不提供 `layer` 自动推断开关（约束 6：不得由文件名推断主体）；不提供「结论复用/缓存」。

## 7. 失败语义对照表

颜色只用四种：**绿** · **琥珀**（`allow_with_warnings`）· **红**（`block`）· **中性灰（没有结论）**。

**绿色（唯一允许渲染成「通过」的档）必须同时满足五个条件**：
① `decision == allow`；② `matched > 0`；③ 请求带 `include_evidence=true`；
④ `skipped_rules` **非空**且逐条 `reasons` 非空（`every([])` 为真，**空集不算通过**）；
⑤ **没有任何一条 skipped 的原因属于「需要验证器证据 / 缺能力 / 无法评估」**——只允许「维度不适用」这类**范围性**跳过。

> **为什么第 ⑤ 条必须写死（R3 红队发现的真实可达路径）**：`POST /v1/policy/evaluate` 今天**不传 `evidence`**（【读码】`src/policy_api/runtime.py` 的判定调用），
> 于是证据类规则整批进 `extra_skipped` 并带「需要验证器证据」原因。此时 `allow + matched>0 + reasons 非空` **会求值为真**，
> 界面就会给一个「几十条规则从未被评估」的结果涂绿。凡出现第 ⑤ 类跳过，一律渲染为 **中性灰 · 没有结论（规则未评估）**，并给出补证据的 CLI 命令。
每个状态色**必须配一个文字标签**（allow / allow_with_warnings / block / 没有结论），颜色不得是唯一信号。

| 档 | 后端事实 | 界面文案（唯一允许的措辞） | 颜色 | 可点击动作 | **禁止渲染成** |
| --- | --- | --- | --- | --- | --- |
| 结论 | `decision=block` | 「判定：阻断」+ 逐条 violation（rule_id@version / 级别 / 消息） | 红 | 打开证据抽屉、重跑 | 「失败」（传输层措辞）、「再试一次就通过」 |
| 结论 | `required_action=approval` | 「需要人工审批后才能继续」 | 红 | 只读展示 | 黄色提示、「稍后自动通过」 |
| 结论 | `allow_with_warnings` | 「判定：允许，但有 N 条告警（不阻断）」 | 琥珀 | 打开证据抽屉 | 「通过」；与 block 共用红色 |
| 结论 | `allow` + `matched>0` + `skipped_rules` 非空且全部有 reasons + **无「需要验证器证据 / 缺能力」类跳过** | 「本批规则判定通过」（范围性跳过另列） | 绿 | 打开证据抽屉 | 把 skipped 计入 violations；把「规则未评估」渲染成通过 |
| **未评估** | `allow` + `matched>0` + **存在「需要验证器证据 / 缺能力」类跳过** | 「**没有结论**：N 条规则未评估（缺验证器证据）」 | 中性 | 打开证据抽屉、给出补证据的 CLI 命令 | 「通过」「检查通过」「合规」 |
| 无覆盖 | `allow` + `matched=0` | 「**没有规则覆盖这次上下文**（不是通过）」 | 中性 | 展开 skipped 明细、补上下文重跑 | 「检查通过」「合规」 |
| 跳过 | `skipped_rules` 有值 | 「有 N 条规则**被跳过**，原因：…」（逐条列 reasons） | 中性 | 逐条展开 | 「已检查」「通过」；**只显示计数不显示原因** |
| 跳过 | `skipped>0` 但响应**无** `skipped_rules` 键 | 「**未请求证据明细**——本页恒定带 `include_evidence=true`，若缺失即为契约异常」 | 中性 | 重发带证据请求 | 任何绿色 |
| **没有结论** | 504 `evaluate_timeout` / `retrieve_timeout` / `validate_timeout` | 「超时：**没有结论**」+ 已耗时 / 预算 | 中性 | 重试（`retryable=true`）；调小 `budget_ms` | 任何绿色；「稍后自动放行」 |
| **没有结论** | 503 `rule_set_unavailable` / `knowledge_unavailable` / `validator_unavailable` / `policy_busy` / `idempotency_unavailable` | 「依赖不可用：**没有结论**」 | 中性 | 仅当 `retryable=true` 才给重试 | 「没有规则 = 允许」；自动重试到成功 |
| **没有结论** | 503 `audit_unavailable` | 「服务端拒绝给出决定：决定记不下来，本次没有结论」 | 中性 | 无（`retryable=false`） | 「先跳过审计」；显示成 allow |
| **没有结论** | 429 `rate_limited` | 「请求被限流，稍后重试」 | 中性 | 退避重试 | 静默重试到成功；把限流藏成「慢」 |
| **没有结论** | 503 `idempotency_unavailable`（响应无法完整写入幂等台账） | 「**没有结论**：响应无法可靠重放」 | 中性 | 按 `retryable` 处理；不要生成残缺缓存 | 当成 allow；吞掉错误；伪造 `Idempotency-Replayed` |
| **没有结论** | 409 `idempotency_key_conflict` | 「同一幂等键已有了结论（未重复执行）」 | 中性 | 换新键重发 | 同键换体重发 |
| **没有结论** | 未识别错误码 / 网络失败 | 「未知失败：<code>」+ `request_id` | 中性 | 复制 `request_id` | 归入「其他错误」的绿色 |
| **未核对** | 尚未请求检索或检索不可用 | 「溯源漂移：**未核对**——不构成可提交依据」 | 中性 | **阻断提交**（D4） | 「无漂移」；「提示，可忽略」 |
| 拒绝 | `capability_unavailable` | 语义是**拒绝**（「该 Agent 不具备强制阻断能力，无法治理此类动作」）；但 **6 条 Policy API 契约路由 0 个抛出点**，今天只在 Phase 6 多 Agent 运行时可产生 | — | 契约路由上**不画分支** | 画成路由分支；渲染成「跳过治理」或「没有结论」 |
| 拒绝 | `evidence_unavailable` | 同上一行（同样 0 抛出点） | — | 同上 | 同上 |
| 非判定 | 401 / 403（含 `metrics_forbidden`、`token_scope_mismatch`、`project_not_allowed`） | 原样显示服务端 `code` + `detail` | 中性 | 仅 `token_scope_mismatch` 提示选租户 | 「租户不存在」；改成可重试 |

**被禁止的文案清单**：把 skipped 说成「通过」；把超时说成「通过」或「稍后放行」；把 503 说成「没有规则/允许」；
把 `matched=0` 说成「合规」；把 `allow_with_warnings` 说成「通过」；把 `idempotency_unavailable` 吞成成功；
把 `capability_unavailable` 说成「跳过治理」；把「未核对」说成「无漂移」；把摘要链说成「防篡改日志」；
把审批通过说成「通用许可」；把门禁绿说成「系统健康」。

  顶栏允许折成两行，但**规则集哈希与取数时刻必须同行**（I3）。
- **无 JS 降级【未实现】**：今天原型的全部交互（`?`、灰控件、勾选）都靠 JS/属性（实测：`tabindex` / `aria-*` / `noscript` / `<form>` 在 `console/` 命中 0）。
  降级形态 = 服务端渲染的**只读快照页**：输出最后一次取数的纯 HTML 表 + 该次取数的命令与退出码，**零交互**（连灰控件都不渲染），每张表下写「静态快照，取数时刻 T」。
  判定类页面在无 JS 时**不渲染任何结论色**，只列原始 JSON。落地前提是 P0 的读路由；在那之前降级页只覆盖 CLI 快照部分。
- **可访问性**：**需要**，理由是解释本身是本设计的核心功能（替代命令、缺口编号、跳过原因都在文字层）。
  ① 每个 `?` 用 `<button type="button">` + `aria-expanded` / `aria-describedby`，不用 `<span data-tip>`；
  ② 灰控件用 `aria-disabled="true"` 的**可聚焦**控件（`disabled` 会退出 tab 序列，导致缺口说明对键盘用户不可达）；
  ③ 四种状态色各配文字标签；④ 表格首行 `<th scope>`；⑤ 状态变化用 `aria-live="polite"` 播报，且**超时/503 的播报文案不得出现「通过」**；⑥ 不引入任何 a11y 依赖库（仓库无前端工程，N1）。
