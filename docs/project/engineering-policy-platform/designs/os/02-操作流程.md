## §0 共用口径（D8：三份终稿共用这一段，不许各自表述）

### 0.1 五条铁律

1. **退出码 0 ≠ allow**。退出码只说明命令跑到最后；结论看决策载荷。
   【实测】`python -m adapters.cli inspect --agent dsh --event tests/fixtures/agent_events/dsh/pre-tool-use-edit-block.json --json`（20:36）→ **exit 0 但 `outcome_code=context_error`**（失败关闭发生在载荷里）。
2. **`skipped_rules` ≠ 通过**。跳过必须显示**原因**；缺 `include_evidence=true` 时响应里没有 `skipped_rules[].reasons`，界面不得渲染"通过"。
   【实测】`python -m policy.check examples/good_controller.py --layer service`（20:35）→ exit 0，`ARCH-001@1` 进 `skipped`：`layer service != controller`——"没有规则管它"不是"它合规"。
3. **超时 / 503 / 504 / 429 / `idempotency_unavailable` = 没有结论**，不是"稍后放行"。
   【实测】`python -m policy_api.cli smoke --token local-dev-token`（20:56:12）→ 末尾 `retrieve: 503`（该租户未配检索；服务端返回 `knowledge_unavailable`）。
4. **提交节点的唯一判据**：`pre.checks[check == "approval"].status == "passed"`；`skipped`、`failed`、过期**都不等于通过**（正反例见 §1-E）。
5. **门禁绿只证明检查项通过**（D10）。【实测】同一份工作树里，`python -m policy.check --check-rules` 在 26 条（20:33，`sha256:a6c9655a…`）与 44 条（20:43:24，`sha256:a90e64ac…`）两个状态**都是 exit 0**；CI 的规则集步骤就是这一条命令（`.github/workflows/phase-8.yml:50`，复核命令：`Select-String -Path .github/workflows/phase-8.yml -Pattern 'check-rules'`）。
   终稿**不得**出现"当前全绿"这类总结性断言；只允许写逐条命令 + 退出码 + 取数时刻。

### 0.2 三条附则

- **附则 A（D2）**：数字三元组。示例：规则条数【44（20:56:12，`python -m policy.check --check-rules`）】；受跟踪基线【6（20:55:56，`git ls-files policies`）】。两者并列显示，**差异本身是信号**。
- **附则 B（`dry_run` 的准确语义）**：`precheck` 子命令走 `dry_run=True`：**不产生真实副作用**（不认领 `action_id`、不签发可用授权、不写限流台账），**但仍会追加审计 JSONL**（`src/enforcement/precheck.py:499-500`；【实测】同一批 precheck 输出里 `[passed ] audit allow sequence=406` → `407` → `410` → `411` 连续递增）。
  凡写"dry-run / 预演无副作用"，必须同时写"**但仍写审计**"。
- **附则 C（`capability_unavailable` 必须两句同时写）**：**Phase 6 多 Agent 运行时可达**（真实抛出点在 `src/adapters/runtime.py`，一致性套件断言只读上限必须报它）；**Policy API 的 6 条契约路由里 0 个抛出点**（只有枚举与状态映射；第 7 条是运行时框架自带的 `/v1/openapi.json`）。只写一半会得到相反印象——界面不得为该码在 API 面画分支（D6）。
- **附则 D（D12 隐喻）**：`安装 / 卸载 / 调度器 / 沙箱 / 第二内核` 五个词一律写成"**隐喻，不成立**"；依据必须回到 `file:line` 或 `AGENTS.md` 约束编号。
