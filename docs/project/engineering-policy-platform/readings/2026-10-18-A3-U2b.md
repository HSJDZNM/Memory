## 7 机制（源码/文档读数，不是本次实测）

1. **Hook 在宿主审批之前**：工具调用流水线是 `tools/pre-execute`（可扩展 allow/deny/ask）→ guards →
   `tools/execute` → `tools/post-execute`（`dsh-tools` README）；PreToolUse 是 pre-execute 的
   waterfall。本仓库插件在 allow 时返回 `next()`、**不注入 allow**（`src/adapters/dsh/policy-hook.plugin.mjs#L669-L675`）：
   放行的含义是"没有拒绝"，不会跳过宿主后续的门。
2. **宿主只在沙箱升级时请求审批**：pwsh 工具的审批路径是 `sandbox_permissions` + `justification` 的
   one-shot escalation，经 `ctx.approval` 在 execute 之前解析（`dsh-tool-pwsh` README）；普通命令不请求。
3. **headless 没有 answerer**：`approval/policy=ask` 且组合里没有 answerer 时，请求会解析成 `unavailable` 并
   失败关闭（`dsh-user-approval` README）；每个请求与结果都进会话审计（`approval/asked` /
   `approval/decided`）——所以"0 个事件"= **没有请求**，不是"请求被吞了"。
4. **条子要被找到，配置必须声明 `approval_file`**；注册表不可用时 `bridge_from_config` 直接抛
   `EnforcementUnavailable`（`src/adapters/dsh/enforcement.py#L530-L545`），不会静默放行。

## 8 对 A3 解冻包 §5/§6 与 run-manifest 的影响

### 8.1 ② 命令族成功率（§5.2）

- A 格的证据链能直接支撑 ②：`stage=pre_decision` 的 `payload.decision=allow` + `approval_use`、
  Hook 的 `enforcement_allow`（`grant_id`）、`allow_delegated`、`final_decision.execution_status=delegated`、
  `post_evidence.process.exit_code=0`、`post_validated`。**这次尝试记 1 次通过**，不因宿主审批扣分。
- **"平台放行"不等于"真的执行"**：本探针的 `executed=false`（delegated）只是"没有由平台执行"，真执行要靠
  会话日志 `tool/result`（`isError`）+ `post_evidence.process.exit_code` 两件一起看。若宿主在 Hook 之后
  拒绝（本探针没有发生），该次尝试**不算通过**：② 的分子是"放行且真的进入执行"，宿主拒绝是 `host_stage` 失败，
  单列原因写进 run-manifest；**不能**把它记成"平台治理覆盖了这条命令"——平台的 allow 没有生效，是宿主阶段拦的。
- ② 的 join 键：Hook 记录的 `tool_use_id` = 会话日志 `tool/call.data.callId`；`action_id` = `<session_id>:<callId>`。
  命令原文只在会话日志 `tool/call.arguments`，审计只有 `param_digest`（B-6 依旧成立）。

### 8.2 ① 写动作治理覆盖率（§5.1）

pwsh 是执行类动作、没有文件维度，不进 ① 的分子/分母；但 A 格的宿主执行在受治树里留下
`__pycache__/`（8 个 pyc）与空的 `pytest-cache-files-aml7r8vs/`。这两类是**命令副作用**，必须进 §5.1 的
unmeasured 清单（原清单有点名 `.pytest_cache/` 与"命令副作用（pytest 缓存）"，但没有点名
`pytest-cache-files-*` 这个具体形态，本次观察到的正是这个空目录），否则
`touched_files` 会把它们记成"落地但没经治理的写"。ACL 变化不是文件内容，不影响树哈希。

### 8.3 §3.2 配置模板有一个会拦住 A3 的路径缺陷

§3.2 的模板把 `audit_log` / `registry` / `registry_approved` / `enforcement_ledger` / `approval_file` 都写成
`.policy/...`。但适配器的路径基准是**配置文件所在目录**（`src/adapters/dsh/adapter.py#L754-L759`、`#L1025`），
配置本身就在 `.policy/` 下，于是这些值会解析成 `.policy/.policy/...`。实测（只读，读配置后打印解析结果）：

```
registry           .policy/.policy/tool-registry.yaml               exists=False
registry_approved  .policy/.policy/tool-registry.approved.json      exists=False
audit_log          .policy/.policy/audit.jsonl                      exists=False
approval_file      .policy/.policy/approval.json                    exists=False
```

注册表读不到 → `bridge_from_config` 抛 `EnforcementUnavailable`，启动或门禁失败关闭（不是放行）。
**A3 开跑前必须把 §3.2 的这五个值改成裸文件名**（与 `examples/dsh/b-plan/dsh-adapter.yaml` 和
Governance 树的既有配置同形；A3 树里注册表落地名是 `tool-registry.yaml`，所以本探针写
`audit_log: audit.jsonl`、`registry: tool-registry.yaml`、`approval_file: approval.json`）。
