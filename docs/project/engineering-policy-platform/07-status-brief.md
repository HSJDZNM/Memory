# 07 · 进度简报（给非技术读者）

> 更新时间：2026-10-19（D 门 2 前置包冻结之后）。面向"不写代码、但要知道项目到哪一步"的读者。
> 技术细节、命令与证据指针不在这里——它们在 `05-implementation-plan.md`、`06-plan-progress.md` 与 `readings/` 里；本文只回答四个问题：**在做什么、做到哪了、接下来做什么、你需要做什么。**

## 1 一句话说清项目

我们要给"在电脑上帮你写代码的 AI"配一套**自动质检 + 全程记账**：
它每改一次文件、每跑一条命令，都先按规则检查（不合规就拦住）、并留下记录；任务做完后再对整份代码做一次终检。
目标是：**AI 写出来的代码都经过审验，最终代码符合规则集**——而不是靠它自己说"我写好了"。

## 5 怎么判断"确实在变好"（不靠感觉）

- **体检连续绿**：26 项检查 + 全量测试持续通过（10-18 三次 + 10-19 收口一次；最近一次 26/26、4m34.8s）。
- **每一项改动都有"差集"**：改规则前 vs 改规则后，判定结果逐字段对比；"不应变的"必须一条不变，反例必须仍被拦。
- **读数落盘**：关键结论都写在受跟踪的文档里，不靠聊天记录。
- **跑不成不记成通过**：环境问题（如 Windows 权限、宿主缺失）会明确记"跑不成"并写触发条件。

## 6 提前说清的边界

- 这是**开发与评测基础设施**，不是能下载安装的产品；现阶段产出是"读数与证据"，不是"某功能上线"。
- 样本小（n=1 级别的实验），**不做"提升百分比/统计显著"的结论**。
- 有一条已知缺口仍在：**AI 在自己的代码里直接写文件**，路径范围目前管不住；能力表里已如实标注，真正的答案是后面的"收工终检"（C3）。
- **A3 v2 的 4/4 只说明"构造就绪"，不说明治理有效**；A/B/C 主实验尚未开跑，所以现在没有任何"治理更好用/更差"的结论。
- 「工具脚本写不进去」（`tools/**`）**已用一处配置修复**（treatment，10-19）：代价是那条"证明缺口还在"的常红检查退役，改用两条更窄的期望（同一动作改前被拦/改后被放；5 类真错误两组都拦）。B1（审批参数域）没有做，留作独立项——它需要你亲手签条子，且在这版题目上不会触发。
- 有些"麻烦"是**故意的**：高风险动作必须人工审批，代理不能自己给自己批条子。

## 7 术语小抄

| 词 | 白话解释 |
| --- | --- |
| 规则集 | 一本可评审的"施工规范"，共 43 条 |
| 判定（decision） | 对一次动作的结论：通过 / 通过但有提醒 / 拦住 |
| 审计台账 | 每次动作的"工地日志"，追加写、不可改历史 |
| 覆盖表 | "哪些入口、哪些工具真的被管"的值班表，缺口必须显式写出来 |
| 门禁（本机体检） | 提交/推送前自动跑的一整套检查 |
| 差集（R-d） | 改动前后判定的逐字段对比清单 |
| 阶段 A/B/C/D | 依次是：读数量准 → 小范围修摩擦/堵漏 → 扩协议（终检/批次）→ 对比实验 |
| D 校准（机械补丁） | 用两条固定补丁试拦截器：违规的必须被拦、合规的必须放行；先证明仪器准，再谈对比实验 |
| 解冻 | 你明确授权"可以开始改会影响 通过/拦住 结果的那一项" |
| treatment | 实验里"改后方案"相对"现在方案"动的那一处；本轮是一行配置（让新建 `tools/` 脚本不再被误拦） |
| 尺子（评分器） | 把"任务完成 / 规则遵守 / 架构合理"变成可执行计分的那套冻结清单；改它 = 换判据 |
| 不治理对照组 | 同一道题在"完全不管"的工作区里跑，用来回答"不管能得几分" |
