# 规则文档 → 规则：转化覆盖报告

> 本文是 `docs/architecture/` 的说明之一，配套 [规则文档转化为规则.md](规则文档转化为规则.md)：那边讲**方法与台阶**，
> 这边记录**一次真实走查的结果**——把 `docs/<mirror>/**` 下的离线规范文档逐篇过一遍，判定它能不能成为
> `policies/<domain>/<ID>.yaml` 里的可执行规则；能转的转，转不了的写明为什么。
>
> 判定与数据的口径以代码为准：`src/policy/models.py`（规则 schema）、`src/policy/checkers.py`（6 个 checker）、
> `validation/validators.yaml`（谁产生证据）、`validation/ruff.toml`（诊断码归属）、`knowledge/corpus.yaml`（语料与溯源）、
> `policies/**`（规则本身）。本文与代码冲突时以代码为准。
>
> 复核命令见 §8；本文里的每个数字都可以用那些命令重算。

## 1. 结论

本次走查覆盖六个镜像集合的 284 篇文档。

其中 17 篇被提炼成 38 条可执行规则；其余 267 篇停在 Curated Guidance，逐篇写明了原因。

| 镜像集合 | 篇数 | 产出规则的篇数 | 规则条数 | 停在 Guidance |
| --- | --- | --- | --- | --- |
| `python-pep-code-style` | 14 | 2 | 19 | 12 |
| `owasp-cheatsheets` | 142 | 15 | 19 | 127 |
| `google-eng-practices` | 16 | 0 | 0 | 16 |
| `gitlab-code-review` | 22 | 0 | 0 | 22 |
| `dora-capabilities` | 39 | 0 | 0 | 39 |
| `dotnet-design-guidelines` | 51 | 0 | 0 | 51 |
| **合计** | **284** | **17** | **39** | **267** |

规则集共 43 条。其中 38 条由镜像文档提炼（`source.kind: standard`），5 条是项目自订（`project-policy`）。

三条过程类文档集合（Google / GitLab / DORA）**不是"没读"**。它们确实含有可判定的工程要求，但那些要求在本仓库已被既有规则承载。

具体说：`TESTING-001` 管"改了生产代码必须带测试"，`TESTING-002` 管"相关测试必须通过"。
再写一遍只会得到三条语义重复、严重级别各异的规则。这正是仓库口径里要避免的"看起来在管这件事、实际什么都没查"。
逐篇的判定与原文见 §4。

## 2. 判据：什么才算"转过来了"

一条规则要真的生效，必须同时满足四件事。方法详见 [规则文档转化为规则.md](规则文档转化为规则.md) §1。

1. **来源是本地的**：`source.kind ∈ {project-policy, standard}`，`source.path` 指向仓库里真实存在的文件；
2. **可确定性判定**：`enforcement.checker` 必须是**已实现**的 6 个之一，且有验证器为它声明产证据；
3. **范围可枚举**：只用 `language / layer / module / operation / project / agent` 六个维度表达得出来；
4. **结论落在决策表里**：`severity` 是四值枚举。

另有两约束由代码或环境强制，走查前已实测确认。

| 约束 | 证据 | 后果 |
| --- | --- | --- |
| 每条已发布规则的 `scope.language` 必须是 `python` | `tests/contract/test_validator_protocol.py::test_every_shipped_rule_is_covered_by_a_validator` | 非 Python 的规范**结构性**不能上线（.NET 全本 51 篇即由此淘汰） |
| 本机与 CI 都**没有 mypy** | `python -m validators.cli probe` → `tool.mypy: unavailable` | `type_check` 类规则一律不能启用：工具缺失 = 规则失败关闭，会让所有 Python 文件一次性判红 |

6 个 checker 里这次真正用到的只有 2 个：`style_lint` 与 `missing_docstring`。
前者走 Ruff 0.14.13 的诊断码，后者是内置的 `py.docstring`（标准库 `ast`）。
其余四个各自有明确原因：`forbidden_dependency` 判依赖图，`missing_tests` 与 `failing_tests` 判变更集与测试进程，`type_check` 缺工具。

### 2.1 Ruff 码的归属纪律

规则只声明"要查什么码"，工具**只有被 `select` 的码才会出现在诊断里**。所以：

- **规则声明了没被 select 的码** → 那条规则永远拿不到证据（本次走查真的抓到一次：`S308`）；
- **select 了没有规则归属的码** → 诊断只进 `unmapped_findings` 计数，却不参与判定。

两个方向都由一条契约测试守住，见 `tests/contract/test_validator_protocol.py`：

```text
test_ruff_codes_are_declared_and_selected_in_both_directions
```

`validation/ruff.toml` 顶部的归属表是它的可读版本。`F811`/`F841` 是 Phase 5 遗留（当时选了码但从未有规则归属），在测试里显式登记为豁免，不是给新增留的口子。

## 3. 转化出来的 38 条规则

38 条规则的分布如下。

| 前缀 | 条数 | checker | 来源 |
| --- | --- | --- | --- |
| `DOC-002..DOC-004` | 3 | `style_lint`（D205 / D200 / D401） | `pep-257-docstrings/index.md` |
| `STYLE-003..STYLE-012`、`STYLE-014..STYLE-018` | 15 | `style_lint`（E401/E402/E711/E712/E713/E714/E721/E722/E731/E741、F403/F405、N801/N802/N803/N806/N815/N816、I001） | `pep-8-python-code/index.md` |
| `SEC-001..SEC-012` | 12 | `style_lint`（S102/S307、S301/S302、S303/S324、S105/S106/S107、S323/S501、S506、S602/S605/S607/S609、S608、S313..S318、S310、S311、S308/S611/S701） | 15 篇 OWASP Cheat Sheet |
| `SEC-014/015/017/018/019/021/022` | 7 | `style_lint`（S113、S110/S112、LOG015、TRY400、S104、S312/S321、S612） | 同上 |
| `DOC-001`（既有） | 1 | `missing_docstring` | `pep-257-docstrings/index.md` |

每条规则都配了一对正反例夹具。

- `tests/fixtures/rules/<RULE-ID>/bad.py`：必须命中本规则；
- `tests/fixtures/rules/<RULE-ID>/good.py`：必须不命中本规则。

这条不是靠自律，而是 `tests/integration/test_rule_corpus.py` 的门禁。
它遍历 `policies/` 自发现规则，对每条 `source.kind == standard` 的规则断言两个夹具都存在。
随后走真实验证器流水线（真子进程 Ruff），判定三件事：反例必须命中、正例必须通过、两条都不能被 `skipped_rules` 吞掉。

38 条溯源都登记在 `knowledge/corpus.yaml` 的 `rule_sources` 里。
每条写的是 `dataset + source_path + heading_path`，索引器把它解析成 `chunk_id` 写进 `rule_sources` 表。
于是可以双向查：

```powershell
$env:PYTHONPATH = "src"
python -m retrieval.cli rules --rule SEC-008   # 规则 -> 它来自哪一段原文
python -m retrieval.cli rules --chunk <chunk_id>  # 反向：这段原文被哪条规则引用
```

| 代号 | 含义 |

| a | 流程 / 组织 / 文化 / 镜像自述：不是代码属性 |

## 6. 回写：三个真实修正

走查不是单向的。它把三处代码或数据的问题翻了出来，都按失败关闭的原则修掉。

1. **`source.path` 指不了中文目录**（真缺陷，已修）。`src/policy/models.py` 的 `_REPO_PATH_RE` 原本只允许 ASCII。
   OWASP 镜像的分类目录却是中文（`02_输入验证、注入与文件处理`）。
   于是任何指向镜像原文的规则都会以"路径包含不支持的字符"加载失败。这不是"能不能写中文"的偏好问题：不改它，`source.path` 就只能写不存在的假路径，
   整个"文档 → 规则"的溯源前提塌掉。`src/retrieval/models.py` 早就为同一原因放宽过一次并留下了注释分歧。
   现在两边都允许非 ASCII，结构拒绝与路径元字符的限制保持不变。
   回归用例 `test_repo_path_accepts_non_ascii_segments` 钉住这两个方向。
2. **`S308` 没被 select**。规则声明了它，工具却不会报——那条规则永远拿不到证据。已补进 `validation/ruff.toml`，
   并把这条不变量写成了契约测试（§2.1）。
3. **`select` 与规则归属不一致会静默失效**。同一件事的另一半：新加的契约测试双向检查，
   历史遗留的 `F811`/`F841` 显式登记为豁免而不是假装不存在。

## 7. 现有 6 个 checker 覆盖不到、值得补的五条

按"补上之后能立刻把哪些镜像原文变成规则"排序。**这些是下一步的输入，不是本次的欠账。**

1. **`commit_message`（读 Git 元数据）**。要求来自 `merge_request_workflow/index.md`：提交主题与正文之间要有空行，主题不超过 72 字符。
   `cl-descriptions.md` 另外要求首行是简短摘要、用祈使语气。
   这是整批镜像里最可机器判定的一组要求，而且与 `AGENTS.md` 已有的提交信息约定同向。目前只有人读的约定，没有可执行的规则。
2. **变更体量闸门**：`small-cls.md` 的 100 / 1000 行阈值、`merge_request_workflow` 的 "not contain more than 10 commit messages"。
   需要能读 diff 统计量的 checker。
3. **文档同步**：`looking-for.md` "If a CL changes how users build, test, interact with, or release code, check to see that it also updates associated documentation"。
   `missing_docstring` 只判 Python 对象，判不到"文档文件有没有随代码改"。
4. **`missing_docstring.changed_only`**：给规则体补一个布尔开关（与 `missing_tests.changed_only` 对齐），
   §5 里那条 GitLab 的方法级 docstring 要求就能立刻上线而不误伤存量代码。
5. **凭据与权限类 checker**。`ai/ai-accessible-internal-data.md` 要求：不得用超级用户模式或共享服务账号把 AI 工具接到内部数据上。
   `development/permissions/review_guidelines/index.md` 要求：权限条件只能减权，不能扩权。
   两条都是硬约束。但 Ruff 的 `S1xx/S5xx` 只覆盖"调用了哪个标准库函数"，覆盖不到"用哪个账号连数据"或"策略是否只减不增"。
